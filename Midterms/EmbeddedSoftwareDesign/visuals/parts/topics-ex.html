The exam and how to prepare

The midterm is 33 multiple-choice questions on lessons 00 to 08. The three samples on this page copy its format and spread. This card collects the professor's rules, the study plan, the key contrasts and the fact sheet, with links to the lesson explainers below.

Format

Duration60 minutes
Questions33 multiple choice, one mark each, total 33
AnswersFour options, A–D. Choose exactly one. Only the answer sheet on the cover page is marked
Wrong answersNo penalty, so answer every question. About 1 minute 50 seconds each: mark a best guess and come back
MaterialsNone. Closed book, no notes, no calculator, no electronic devices
PenBlue or black, non-erasable. No pencil, highlighter or correction pen
IdentificationName in capitals, student ID and section number on every page. A wrong section number is penalised

What the questions ask

  • Predict behaviour. "This code does X; what does the board do?" Many are silent failures: the code compiles with no warning, then does nothing or hangs.
  • Calculate by hand. Bit positions and register values for a pin, a 32-bit value in hex, little-endian bytes, an IRQ's vector address, PSC and ARR, BRR. The numbers work without a calculator.
  • Choose the correct line of code out of four, for example the statement that clears a flag correctly.
  • Name the concept: the general idea behind a mechanism, its alternatives, and which one this chip picked.
  • Never asked: writing code, a register address the question does not give, or numbers from a measured run.

How to prepare

  1. 1Answer every "What You Should Be Able to Say" slide at the end of lessons 00–03 out loud, without looking. Each of Topic 0, 1, 2 and 3 answers its slide.
  2. 2Walk the silent-failure checklists: lesson 05 slide 33, lesson 06 slide 17, lesson 08 slide 14. For each row, explain why that symptom follows. The tables with a "why" column are in Topic 5, Topic 6 and Topic 8.
  3. 3Practise the arithmetic until it is automatic: pin bit positions, clear-then-set on a reset value, BSRR values and vector addresses (Topic 5), PSC and ARR (Topic 6), BRR and XOR checksums (Topic 8), little-endian decoding (Topic 0). Start with the practice problems below; every sample has each kind.
  4. 4Know how each flag clears (lesson 08 slide 4, Topic 8) and which priority numbering is in use (lesson 07 slide 9, Topic 7).
  5. 5For each mechanism, know the general idea and this chip's answer: I/O model, address spaces, instruction-set model, flags, return address, address binding, dispatch, mutual exclusion, scheduling. The contrast table below lists them.
  6. 6Bring a blue or black pen. Nothing else is allowed on the desk.

The guide's practice problems

The professor calls these "similar in kind and difficulty to the exam" but not the exam's questions. Try each one, then open it for the answer.

P1Which bits of GPIOB->MODER belong to PB3, and what value makes PB3 an output?

Bits 7:6 (2*n*+1:2*n* with n = 3). Write 01.

P2Write the single BSRR value that sets PB1 high and PB6 low and leaves every other pin of port B alone.

(1u << 1) | (1u << (6 + 16)) = 0x00000002 | 0x00400000 = 0x00400002.

P3PA9 needs alternate function 1. Which register and which bits hold PA9's AF number?

AFR[1] (9 / 8 = 1). 9 mod 8 = 1, so bits 7:4. Write 0001.

P4GPIOA->PUPDR reads 0x24000000. What does it read after enabling a pull-up on PA4 with the clear-then-set idiom?

PA4's field is bits 9:8. Clearing them leaves 0x24000000, and OR-ing 1 << 8 gives 0x24000100.

P5EXTI4_15_IRQn is IRQ 7. What is its vector number, and at which address is its vector?

Vector 16 + 7 = 23. Address 0x08000000 + 23 × 4 = 0x08000000 + 92 = 0x0800005C.

P6At 48 MHz, choose PSC and ARR for a timer that counts at 1 MHz and updates every 1 ms.

PSC = 47 (48 MHz / 48 = 1 MHz). ARR = 999 (1000 counts = 1 ms).

P7What value of BRR gives 9600 baud at 48 MHz, and how long does one byte take on the wire?

48 000 000 / 9600 = 5000. One byte = 10 bits / 9600 ≈ 1.04 ms.

P8start = 0xFFFFFF00 and now millis() returns 0x00000100. What does millis() - start give, and is a 500 ms timeout expired?

0x00000100 − 0xFFFFFF00 = 0x00000200 = 512 ms, modulo 2³². Yes, 512 ≥ 500, so it has expired. Compare the wrong form, millis() >= start + 500. Here start + 500 wraps to 0x000000F4. Only 16 ms after start, when millis() is 0xFFFFFF10, that test is already true, so the timeout fires about 484 ms early. Only the subtraction form is always right.

P9Compute the NMEA checksum of the body LED,1.

L=0x4C, E=0x45, D=0x44, ,=0x2C, 1=0x31. 4C ^ 45 = 09, ^ 44 = 4D, ^ 2C = 61, ^ 31 = 50. Frame: **$LED,1*50**.

P10The first data record of a hex file contains the bytes 00 30 00 20 C5 06 00 08. What are the initial SP and the reset handler's actual address?

Little-endian: SP = 0x20003000 (top of 12 KB RAM). Reset vector = 0x080006C5, so the handler is at 0x080006C4 (bit 0 is the Thumb bit).

P11Sort these by where they live and whether they cost flash: const char msg[] = "hi";, int total;, int limit = 50;.

msg: .rodata, flash only. total: .bss, RAM only, no flash. limit: .data, RAM and flash.

P12A global uint32_t is written only by an ISR and only read by main(). Does it need volatile? Does it need a critical section?

It needs volatile, so main() really reads it each time. It does not need a critical section: it is a single aligned word with one writer, so it can't tear.

P13A task of priority 2 in this course's kernel and an interrupt of NVIC priority 2. Which numbering treats a larger number as more urgent?

The kernel (like FreeRTOS): a higher number is more urgent. In the NVIC, 0 is the most urgent.

P14Why can't an interrupt handler call os_mutex_lock()?

Locking may have to block, putting the caller to sleep until the owner unlocks. A handler is not a task; there is nothing to put to sleep, so an ISR must use non-blocking APIs such as os_queue_put_from_isr(). ---

Exam line

33 questions in 60 minutes, no calculator, no penalty for guessing. Know the arithmetic cold, know how every flag clears, and for every mechanism know the general idea, the alternative, and this chip's choice.
