Question 18 · L05, Clear-then-set on MODER

GPIOA->MODER holds its reset value 0xEBFFFFFF. The program runs the line below to make PA6 an output. What does GPIOA->MODER read afterwards?

GPIOA->MODER = (GPIOA->MODER & ~(3u << 12)) | (1u << 12);
  1. A 0xEBFFDFFF Correct. Bits 13:12 go from 11 to 01, and no other bit changes.
  2. B 0x00001000 No. That is MODER = 1u << 12, which also makes the other 15 pins inputs, the debug pins included.
  3. C 0xEBFFFFFF No. That is what MODER |= 1u << 12 alone leaves. OR turns 11 into 11, still analog.
  4. D 0xEBFFEFFF No. Its bits 13:12 read 10, alternate function.

Answer: A. PA6's field is bits 13:12 (2n = 12). The mask 3u << 12 = 0x00003000 clears it, giving 0xEBFFCFFF, and OR-ing 1u << 12 = 0x00001000 writes 01 there.

The hex digit that holds pins 7 and 6 goes from F (11 11) to D (11 01), so the result is 0xEBFFDFFF. A plain = (B) rewrites all 16 pins, an OR alone (C) cannot clear the 11, and D writes 10.

Exam line

Pin n's MODER field is bits 2n+1 : 2n. Clear it with & ~(3u << 2n), then set it with | (mode << 2n), and only that field changes. |= alone cannot clear an 11, and a plain = rewrites every pin.

Question 19 · L05, One BSRR write

One write must turn PB2 on (high) and PB7 off (low) and leave every other pin of port B as it is. Which line does that?

  1. A GPIOB->BSRR = 0x00000084; No. Bits 7 and 2 are both in the set half, so PB7 goes high as well.
  2. B GPIOB->BSRR = 0x00800004; Correct. Bit 2 sets PB2, bit 23 = 7 + 16 resets PB7, and every 0 leaves its pin alone.
  3. C GPIOB->BSRR = 0x00040080; No. The halves are swapped, so it resets PB2 and sets PB7.
  4. D GPIOB->ODR = 0x00000004; No. It is one store and gets PB2 and PB7 right, and it also forces every other port-B pin low.

Answer: B. In BSRR, bit n sets pin n and bit n + 16 resets it. PB2 needs bit 2 (0x00000004) and PB7 needs bit 23 (0x00800000), so the value is 0x00800004.

A 0 bit in either half means leave this pin alone, so one store sets some pins, resets others and ignores the rest. Writing ODR (D) gives every pin a level, so the pins that were on go off.

Exam line

BSRR: a 1 at bit n sets pin n high, a 1 at bit n + 16 sets it low, a 0 changes nothing. PB2 high and PB7 low is (1u << 2) | (1u << 23) = 0x00800004.

Question 20 · L05, IRQ to vector address

A button on PB3 is to raise an interrupt through EXTI. On this chip EXTI lines 0–1 share IRQ 5, lines 2–3 share IRQ 6, and lines 4–15 share IRQ 7. Which IRQ fires, what is its vector number, and at which address is its vector?

  1. A IRQ 3, vector 19, address 0x0800004C No. 3 is the line number. Line 3 arrives as IRQ 6.
  2. B IRQ 6, vector 22, address 0x08000016 No. It adds 22 bytes instead of 22 vectors of 4 bytes each.
  3. C IRQ 6, vector 22, address 0x08000058 Correct. 16 + 6 = 22, and 22 × 4 = 88 = 0x58.
  4. D IRQ 6, vector 6, address 0x08000018 No. It forgets the 16 core vectors in front of the IRQs.

Answer: C. PB3 is pin 3, so it feeds EXTI line 3 once EXTICR selects port B, and line 3 reaches the NVIC as IRQ 6.

The first 16 vectors belong to the core, so IRQ 6 is vector 16 + 6 = 22. Each vector is a 4-byte address, so it sits at 0x08000000 + 22 × 4 = 0x08000000 + 0x58 = 0x08000058.

Exam line

Vector number = 16 + IRQ, vector address = 0x08000000 + (16 + IRQ) × 4. EXTI lines 2–3 share IRQ 6, so PB3's vector is 22, at 0x08000058.

Question 21 · L05, Silent failure: input mode not written

Button A (PA0, wired to GND, internal pull-up on) is polled every 1 ms through the debouncer, and it works. A student deletes the line below and rebuilds. The build has zero warnings. What does the program see from button A now?

pin_mode(GPIOA, 0, MODE_INPUT);
  1. A A button that is always pressed, because PA0 stays analog and an analog pin reads 0 in IDR Correct. Slide 33, row 2. Analog reads 0, and 0 means pressed for an active-low button.
  2. B Random presses nobody made, because the released pin now floats No. That is a missing pull-up (row 3), and PUPDR is still written.
  3. C Nothing at all, because writes to port A now vanish and reads return 0 No. That is a missing IOPENR clock gate (row 1), which this change does not touch.
  4. D The same as before, because input is the mode every pin has after reset No. Every pin except PA13 and PA14 resets to 11, analog.

Answer: A. MODER resets to 0xEBFFFFFF, so PA0's field stays 11, analog. An analog pin is disconnected from the digital logic and reads 0 in IDR whatever the voltage on it.

Button A is active low, so button_down() returns true from the first sample. The debouncer accepts one press about 20 ms after reset that nobody made, and after that the level never moves again. Input mode is written, never assumed.

Exam line

Every pin wakes up analog (11) except PA13 and PA14. An analog pin reads 0 in IDR, so a forgotten input mode makes an active-low button read pressed forever, with zero warnings.

Question 22 · L05, Polling vs interrupt

Both buttons bounce. For one press, polled button A (sampled every 1 ms) reports one level change, now and then three, while button B's EXTI handler counts tens of edges. Why do the counts differ?

  1. A EXTI records each edge twice, once in RPR1 and once in FPR1 No. Each edge sets one bit, a rising edge in RPR1 and a falling edge in FPR1.
  2. B debounce_step() removes button A's bounce before the level changes are counted No. changes counts every move of the raw sample, before the debouncer accepts anything.
  3. C A 1 kHz poll sees only the level at each sample, so most bounce transitions, microseconds apart, fall between samples, while EXTI latches every edge Correct. Polling at 1 kHz is a filter; the interrupt sees what actually happened.
  4. D Button B bounces more, because a pin used for an interrupt has no pull-up No. Both buttons have the same pull-up and the same bounce.

Answer: C. A press bounces for about a millisecond, with transitions microseconds apart. Button A is looked at once per millisecond, so most transitions fall between two samples and are never seen. Polling is a filter.

EXTI latches every edge in hardware, and with both RTSR1 and FTSR1 set, button B's handler runs once per bounce edge. Neither count is wrong. The poll sees a sampled summary, the interrupt sees every edge.

Exam line

Polling at 1 kHz is a filter. Bounce transitions are microseconds apart, and most fall between samples. An interrupt latches every edge, wanted or not, so the same press gives 1 poll change and tens of EXTI edges.
