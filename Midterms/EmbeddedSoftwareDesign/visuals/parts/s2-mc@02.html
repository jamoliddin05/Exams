Question 9 · L02, Declare vs define

startup.c sets SystemCoreClock and main.c reads it. Both files include clock.h. Which arrangement builds and links without an error?

  1. A uint32_t SystemCoreClock = 12000000; in both startup.c and main.c No. Two definitions: multiple definition of SystemCoreClock. The linker will not choose for you.
  2. B extern uint32_t SystemCoreClock; in clock.h, and no definition anywhere No. Two needs and no definition: undefined reference to SystemCoreClock.
  3. C extern uint32_t SystemCoreClock; in clock.h, plus uint32_t SystemCoreClock = 12000000; in startup.c only Correct. One declaration shared by both files, exactly one definition.
  4. D uint32_t SystemCoreClock = 12000000; in clock.h No. The preprocessor pastes the header into both files, so both objects define it: multiple definition.

Answer: C. Each .c file is compiled alone. extern is a declaration, so main.o leaves a hole and a note saying it needs SystemCoreClock. The linker matches every need to exactly one definition, and C has exactly one, in startup.o.

A and D give two definitions, since a definition in a header lands in every file that includes it, and the linker stops with multiple definition. B gives none, and the linker stops with undefined reference to SystemCoreClock, the error the course's spike really hit.

Exam line

The linker matches every "needs" to exactly one "defines". None left over, none duplicated, or it refuses: undefined reference to X means nobody defines X, multiple definition of X means two files do. Declare with extern in the header, define in one .c file.

Question 10 · L02, Intel HEX address

A hex file for the STM32C031C6 contains these two consecutive records. At which address is the first data byte of the second record (0A) programmed?

:020000040800F2
:100120000A4B1B68013B0B4A13600B4B1A68FF21FB
  1. A 0x00000120 No. That ignores the type-04 record. It would be right only if all of flash fit in 16 bits of address.
  2. B 0x08000120 Correct. Upper 16 bits 0800 from record 1, lower 16 bits 0120 from record 2.
  3. C 0x08000010 No. 10 is the byte count LL, the first field after the colon. The offset is the next four digits.
  4. D 0x00000920 No. That adds 0x0800 + 0x0120. The 04 record supplies the upper half of the address, so it is shifted 16 bits up.

Answer: B. The first record has type 04, extended linear address: its data 0800 becomes the upper 16 bits of every following address. The second record reads 10 (16 data bytes), 0120 (offset) and 00 (data).

So the address is 0x0800 in the upper half and 0x0120 in the lower half, 0x08000120. An 8-bit AVR never needed the 04 record, because its whole flash fits in 16 bits of address. This chip's flash starts at 0x08000000.

Exam line

Record :LL AAAA TT data CC. Type 04, extended linear address, sets the upper 16 bits: after :020000040800F2, offset 0x0120 means 0x08000120. The 8-bit chips never needed it, because their flash fits in 16 bits of address.

Question 11 · L02, Address binding

On a laptop, two programs run at the same time, and each keeps its own data at address 0x400000 without disturbing the other. What makes this possible, and why can't the STM32C031C6 do the same?

  1. A The compiler gives each program its own 0x400000; the chip's compiler cannot, because the chip has only one RAM No. The compiler sees one file at a time and fixes no final address at all.
  2. B The loader moves one of the two programs to a free address when it starts; the chip has no loader No. That is load-time binding. The moved program would then use a different address, not 0x400000.
  3. C An MMU translates every address while the programs run (run-time binding), so 0x400000 means a different physical place for each; the chip has no MMU, so its addresses are bound at build time and each is one real location Correct. Run-time binding needs an MMU, and this chip has none.
  4. D The OS saves one program's 0x400000 to disk while the other runs; the chip has no disk No. Swapping to disk does not let two running programs use the same address. Translation does.

Answer: C. This is run-time binding. An MMU translates each program's addresses while it runs, so two programs can both believe they own 0x400000, in the slide's words.

This chip has no MMU and no loader, so binding happens at build time and is burned into the image. 0x20000000 is one real SRAM word for every piece of code that uses it.

Exam line

Three moments to bind: compile time, load time, run time. A desktop binds at run time and needs an MMU. This chip has no loader and no MMU, so binding happens at build time and is burned into the image.
