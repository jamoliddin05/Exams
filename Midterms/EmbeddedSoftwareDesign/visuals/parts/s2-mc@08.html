Question 31 · L08, BRR for the wrong clock

A firmware sets USART2->BRR = 417, computed for 48 MHz and 115 200 baud, but it never raises the clock: the core and USART2 still run at the reset 12 MHz. The PC terminal is set to 115 200 baud, 8N1. What does the terminal show when the board prints its banner?

  1. A Nothing at all: USART2 cannot run from a 12 MHz clock No. USART2 runs from whatever clock it gets; only the bit rate changes. "Nothing sent" is the symptom of a missing USART2EN.
  2. B Garbage characters Correct. 12 000 000 / 417 ≈ 28 800 baud, a quarter of 115 200, so the terminal samples the wrong bits.
  3. C The banner, arriving four times more slowly No. A UART sends no clock. The terminal keeps its own 115 200 baud and cannot follow a slower sender.
  4. D The banner: the receiver resynchronises on every start bit, so the rate error does not matter No. Resynchronising on each start bit absorbs a few percent. This error is 75 %.

Answer: B. BRR counts clocks per bit. 417 clocks of a 12 MHz clock last four times as long as 417 clocks of 48 MHz, so the board sends at 12 000 000 / 417 ≈ 28 800 baud while the terminal expects 115 200.

The terminal times every bit by its own clock. It sees the falling edge of the start bit, then samples eight data bits and the stop bit 8.7 µs apart, all inside the board's first three 34.75 µs bits. The bytes it builds are wrong, often with a framing error. Slide 14 calls BRR for the wrong clock "the most recognisable UART fault". At 12 MHz the right value is 12 000 000 / 115 200 = 104.17 → 104.

Exam line

BRR = clock / baud, so it is only right for the clock it was computed for. 417 at the reset 12 MHz gives about 28 800 baud, and the terminal shows garbage characters, the most recognisable UART fault.

Question 32 · L08, What XOR can and cannot detect

The board receives four damaged copies of the frame $LED,85*6C. In ASCII, 4 = 0x34, 5 = 0x35, 6 = 0x36, 8 = 0x38, 9 = 0x39. Which one passes the board's checksum check?

  1. A $LED,84*6C No. 5 → 4 flips one bit. XOR catches every single flipped bit: the body gives 6D.
  2. B $LED,86*6C No. 5 → 6 flips bits 0 and 1 of the same byte (35 ^ 36 = 03). Two different columns change: 6F.
  3. C $LED,94*6C Correct. 8 → 9 and 5 → 4 both flip bit 0. The two flips cancel and the body still gives 6C.
  4. D $LED,8*6C No. The lost 5 takes 0x35 out of the XOR: 6C ^ 35 = 59.

Answer: C. Each bit of the checksum is the parity of one bit column of the body: 1 when the column holds an odd number of 1s. A change shows only if it changes some column's parity.

In $LED,94 two bytes are damaged, and each damage flips bit 0. Column b0 changes twice, so its parity is back where it started and the checksum still matches. The board accepts the frame and sets the bar to 94 instead of 85. Slide 10: XOR does not catch "two errors in the same bit position of different bytes"; a CRC would.

Exam line

XOR catches any single flipped bit and any change inside one byte. It misses two errors in the same bit position of different bytes, because they cancel: $LED,94*6C passes as if it were $LED,85*6C.

Question 33 · L08, How a flag clears

Each line below is meant to clear the interrupt flag named after it, on the STM32C031. Which line does clear it?

  1. A uint8_t c = (uint8_t)USART2->RDR; for USART2 RXNE Correct. Reading RDR takes the byte and clears RXNE.
  2. B USART2->ISR &= ~USART_ISR_TXE; for USART2 TXE No. ISR is read only, so the write is ignored. TXE clears when a byte is written to TDR.
  3. C TIM3->SR = TIM_SR_UIF; for TIM3 UIF No. UIF clears by writing 0. This writes 1 to UIF, which leaves it set, and 0 to every other flag, which clears them.
  4. D EXTI->FPR1 &= ~(1u << 1); for EXTI line 1 No. FPR1 clears by writing 1. This writes 0 to bit 1, which does nothing, and writes back the other pending 1s, which clears them.

Answer: A. Slide 4 counts five ways a flag clears on this one chip: EXTI write 1, TIM UIF write 0, CC1IF read CCR1, RXNE / TXE read RDR / write TDR, and ORE write 1 to ICR. Only line A matches its flag.

B, C and D each use another flag's habit, and each leaves its own flag set. C and D also clear flags nobody handled. The right lines are USART2->TDR = byte, TIM3->SR = ~TIM_SR_UIF and EXTI->FPR1 = 1u << 1.

Exam line

Five conventions on one chip: EXTI write 1, UIF write 0, CC1IF read CCR1, RXNE / TXE read RDR / write TDR, ORE write 1 to ICR. For every flag, look up how it clears.
