Question 5 · L01, Condition codes vs compare-and-branch

With signed ints, if (a < b) goto L; compiles to one instruction on RISC-V, blt a0, a1, L, but to two on the Cortex-M0+, cmp r0, r1 and then blt L. What is the reason?

  1. AThe Cortex-M0+ is a condition-code machine: cmp subtracts, throws the result away and sets N Z C V in APSR, and the next branch reads those flags; RISC-V has no flags register and compares inside the branchCorrect. Compare sets the flags, a later branch reads them.
  2. BThe Cortex-M0+ is a register–memory machine, so cmp must first fetch a and b from memoryNo. Both machines are load–store, and cmp r0, r1 compares two registers.
  3. Ccmp writes a − b into r0, and blt then tests whether r0 is negativeNo. cmp discards the difference. r0 still holds a; only the flags change.
  4. DARM flags can feed only one branch, so a cmp must come before every conditional branchNo. It is the other way round: one cmp can feed several branches. That density is what flags buy.

Answer: A. This chip remembers a comparison in four flag bits at the top of APSR. cmp is a subtraction that throws the answer away and keeps the flags, and a later branch reads them. RISC-V is a compare-and-branch machine: it has no flags register, so blt a0, a1, L compares and branches in one instruction.

Flags buy density, because one cmp can feed several branches. They cost a hidden link between two instructions that everything in between must preserve, which is why newer designs such as RISC-V dropped them.

Exam line

This chip is a condition-code machine: cmp sets N Z C V in APSR and the next branch reads them. RISC-V and MIPS compare and branch in one instruction and have no flags. Flags buy density: one cmp feeds several branches.

Question 6 · L01, Link register

main calls this hand-written function with bl log_value. uart_send is a leaf function that returns with bx lr. What happens when log_value runs?

08000300 <log_value>:
 8000300:  movs  r0, #65
 8000302:  bl    8000400 <uart_send>
 8000306:  bx    lr
  1. AIt returns to main normally, because bl log_value pushed main's return address onto the stackNo. That is a stack-based machine such as the AVR. Here bl writes the return address into LR only.
  2. BIt never returns: bl uart_send overwrote LR with 0x08000307, so bx lr keeps branching to itselfCorrect. LR holds one return address, and the inner bl replaced it.
  3. CIt returns to main normally, because uart_send restores main's return address in LR before it returnsNo. uart_send never saw main's address. Nothing writes it back.
  4. DIt HardFaults at bx lr, because LR holds an even addressNo. bl always sets bit 0, so LR is 0x08000307, odd.

Answer: B. This chip keeps a return address in one link register. bl log_value put the way back to main in LR. bl uart_send at 0x08000302 is 4 bytes long, so it replaced LR with 0x08000306 | 1 = 0x08000307.

After uart_send returns, bx lr branches to 0x08000306, which is the bx lr itself. The board hangs with no error. A function that calls another must save LR first with push {lr} and return with pop {pc}.

Exam line

This chip is a link-register machine: bl writes the return address into LR, not to the stack. LR holds only one, so a function that calls another must push {lr} first; that is what the push in every non-leaf prologue is for.

Question 7 · L01, Read-modify-write on a load–store machine

r1 holds the GPIOA base address, ODR is at offset 0x14, and r0 holds 0x20. Which instruction sequence does the Cortex-M0+ execute for GPIOA->ODR |= (1u << 5);?

  1. Aorrs [r1, #0x14], r0No. An ALU operand in memory is the register–memory model. The M0+ is load–store and has no such instruction, nor an AVR-style sbi.
  2. Bldr r2, [r1, #0x14], then bics r2, r0, then str r2, [r1, #0x14]No. bics is &= ~: this clears PA5.
  3. Cstr r0, [r1, #0x14]No. That is ODR = 0x20: it switches off every other pin of port A.
  4. Dldr r2, [r1, #0x14], then orrs r2, r0, then str r2, [r1, #0x14]Correct. Read, modify, write: three instructions, two bus accesses.

Answer: D. The M0+ is load–store: the ALU takes registers only. So |= on a register in memory is a read (ldr), a modify (orrs, the |) and a write (str). That is three instructions, two bus accesses, and a gap between the read and the write that belongs to whatever runs next.

The AVR could set a bit with one sbi. The M0+ has no such instruction; the convenience comes back as hardware, the GPIO BSRR register of lesson 05.

Exam line

Load–store: setting one bit in a peripheral register is never one instruction here. It is ldr, orrs (or bics to clear), str: three instructions, two bus accesses, and a gap. The M0+ has no sbi.

Question 8 · L01, Immediate offset range

r4 holds the base address of a peripheral with 32-bit registers. On the Cortex-M0+, which of these loads cannot be encoded as one 16-bit ldr, so the compiler must first add to the base (a Cortex-M4 does it in one instruction)?

  1. Aldr r0, [r4, #0x1C]No. 28 bytes = 7 words, fits the 5-bit field. This is USART2->ISR on slide 10.
  2. Bldr r0, [r4, #0x7C]No. 124 bytes = 31 words, the largest value that fits in 5 bits.
  3. Cldr r0, [r4, #0x80]Correct. 128 bytes = 32 words, which needs 6 bits.
  4. Dldr r0, [r4, #0x40]No. 64 bytes = 16 words, fits.

Answer: C. The 16-bit ldr Rt, [Rn, #imm] keeps its offset in a 5-bit field counted in words. It reaches 0 to 31 × 4 = 124 bytes. 0x80 = 128 bytes = 32 words, one past the limit, so the compiler first moves the base with an add.

The other three fit: 0x1C = 28 (field 7), 0x7C = 124 (field 31) and 0x40 = 64 (field 16). A Cortex-M3 or M4 has a 32-bit ldr that reaches ±4095 bytes.

Exam line

16-bit ldr: 5-bit offset × 4, so 0 to 124 bytes, positive only (ldrh 0–62, ldrb 0–31, [sp, #n] 0–1020). A field beyond that costs an extra add. Cortex-M3/M4 reach ±4095.
