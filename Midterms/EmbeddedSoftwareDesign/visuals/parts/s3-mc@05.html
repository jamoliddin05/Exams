Question 18 · L05, Reading one IDR bit

Button C is wired from PA9 to GND, and PA9 is an input with the internal pull-up. GPIOA->IDR reads 0x0000A5F3. What does (GPIOA->IDR >> 9) & 1u give, and is button C pressed?

  1. A 1, so button C is released No. Bits 10 and 8 are 1. Bit 9, between them, is 0.
  2. B 0, so button C is released No. With a pull-up and a switch to GND the button is active low, so 0 is pressed.
  3. C 0x52, so button C is released No. 0x52 is IDR >> 9 without the mask. & 1u keeps only bit 0.
  4. D 0, so button C is pressed Correct. Bits 11:8 are the digit 5 = 0101, so bit 9 is 0, and 0 means pressed.

Answer: D. One hex digit is four bits, so 0xA5F3 is 1010 0101 1111 0011, and the digit 5 holds bits 11:8 = 0101. Bit 9 is 0. Shifting right by 9 brings bit 9 down to bit 0, and & 1u clears every other bit, so the expression is 0.

Released, the pull-up holds PA9 at 3.3 V and the bit reads 1. Pressed, the switch pulls PA9 to GND and the bit reads 0, so 0 means pressed.

Exam line

Read pin n with (IDR >> n) & 1u. With a pull-up and a switch to GND the button is active low, so 0 means pressed. 0xA5F3 has bit 9 = 0 (digit 5 = 0101).

Question 19 · L05, Why BSRR is the safe one

main() used to turn PA5 on and PA4 off with the two lines below, and now and then PA6, which an interrupt handler turns on, went off again. It now runs GPIOA->BSRR = 0x00100020; instead. What does that write do, and why can the handler's change no longer be lost?

GPIOA->ODR |= 1u << 5;
GPIOA->ODR &= ~(1u << 4);
  1. A PA5 goes high and PA4 goes low in one store that reads nothing, so there is no stale copy of the port to write back Correct. Bit 5 sets PA5, bit 20 = 4 + 16 resets PA4, and with no load there is no stale copy.
  2. B PA5 goes high and PA4 goes low, and the handler's change is kept because BSRR is volatile and ODR is not No. volatile only makes every access happen. It cannot stop an interrupt between a load and a store.
  3. C PA5 goes high and every other pin of port A goes low, so PA6 still turns off No. That treats a 0 bit as low. In BSRR a 0 leaves its pin alone.
  4. D PA4 goes high and PA5 goes low, in one store that an interrupt cannot split No. The halves are swapped. Bit 5 is in the set half, bits 15:0.

Answer: A. In 0x00100020 the set half (bits 15:0) is 0x0020, bit 5, so PA5 goes high, and the reset half (bits 31:16) is 0x0010, bit 20 = 4 + 16, so PA4 goes low. Every 0 bit leaves its pin alone, PA6 included.

Each ODR line is a load, a change and a store. A handler that runs between main()'s load and store sets PA6, and main() then stores its stale copy without PA6. BSRR needs no load, so the write is one store, and an interrupt lands before it or after it.

Exam line

ODR |= and ODR &= are load, change, store, and an interrupt between the load and the store is undone by the stale copy. BSRR is one store with no read, so it is atomic. 0x00100020 sets PA5 (bit 5) and resets PA4 (bit 20 = 4 + 16).

Question 20 · L05, Vector address to IRQ

The vector table starts at 0x08000000. The word at address 0x08000070 reads 0x08000A1D. Which IRQ is this vector for, and where does its handler's first instruction sit?

  1. A IRQ 12; the handler starts at 0x08000A1C Correct. 0x70 / 4 = 28, 28 − 16 = 12, and bit 0 of the word is the Thumb bit.
  2. B IRQ 28; the handler starts at 0x08000A1C No. 28 is the vector number. The first 16 vectors are the core's, so the IRQ is 28 − 16.
  3. C IRQ 12; the handler starts at 0x08000A1D No. Bit 0 is the Thumb bit. Thumb instructions sit at even addresses.
  4. D IRQ 12; the handler starts at 0x08000070 No. That is where the vector is stored. The handler's address is the word stored there.

Answer: A. 0x08000070 is 0x70 = 112 bytes into the table, and each vector is 4 bytes, so this is vector 112 / 4 = 28. The first 16 vectors belong to the core, so vector 28 is IRQ 28 − 16 = 12.

The word stored there is the handler's address with bit 0 set, the Thumb bit. The last hex digit D = 1101 loses its bit 0 and becomes C = 1100, so the handler's first instruction is at 0x08000A1C.

Exam line

Vector number = (address − 0x08000000) / 4 and IRQ = vector − 16, so 0x08000070 is vector 28, IRQ 12. The stored word has bit 0 set (Thumb), so the handler starts at 0x08000A1C.

Question 21 · L05, Silent failure: EXTICR

A third button is wired from PB9 to GND. It is set up with the lines below, and EXTI4_15_IRQHandler checks and clears bit 9 correctly. EXTICR is never written. The build has zero warnings. What happens when the PB9 button is pressed?

RCC->IOPENR |= RCC_IOPENR_GPIOBEN;
pin_mode(GPIOB, 9, MODE_INPUT);
pin_pull(GPIOB, 9, PULL_UP);
EXTI->FTSR1 |= 1u << 9;
EXTI->FPR1   = 1u << 9;
EXTI->IMR1  |= 1u << 9;
NVIC_EnableIRQ(EXTI4_15_IRQn);
  1. A It works, because the reset value of EXTICR lets every port's pin 9 into line 9 No. Each line is a multiplexer and passes one port's pin at a time. Code 0 picks port A.
  2. B The first press jumps to Default_Handler and the board hangs No. That is a misspelt handler name (slide 33, row 7). The name here is right.
  3. C The edge latches in FPR1 bit 9 but never reaches the NVIC No. That is a missing IMR1 (row 5). Here no edge reaches EXTI, so FPR1 bit 9 stays 0.
  4. D Nothing happens, because line 9 still selects port A and watches PA9 Correct. EXTICR[2] bits 15:8 reset to 0, port A, so PB9's edges never reach line 9.

Answer: D. EXTI line 9 watches pin 9 of one port, chosen by line 9's field in EXTICR[9 / 4] = EXTICR[2], bits 8 × 1 + 7 : 8 × 1 = 15:8. That field resets to 0, port A, so the line watches PA9. PB9's edge never reaches EXTI, FPR1 bit 9 stays 0, and the handler never runs.

The fix is port code 1 in that field, EXTICR[2] = 0x00000100. A port-A button works without it, by luck, because port A's code is the reset value.

Exam line

EXTI line n watches pin n of one port, chosen by EXTICR[n / 4] bits 8(n mod 4)+7 : 8(n mod 4). Code 0, port A, is the reset value, so a forgotten EXTICR works on port A by luck and is dead on any other port.

Question 22 · L05, Write 1 to clear

EXTI4_15_IRQHandler serves lines 4 to 15. After it has handled line 9's falling edge, it must clear line 9's pending bit and leave every other line's pending edge for the next call. Which line does that?

  1. A EXTI->FPR1 |= 1u << 9; No. |= reads FPR1 first and writes every pending 1 back, which clears those lines too.
  2. B EXTI->FPR1 = 1u << 9; Correct. The 1 clears bit 9, and the 0s leave every other line pending.
  3. C EXTI->FPR1 &= ~(1u << 9); No. It writes 0 to bit 9, which clears nothing, and 1 to every other pending line, which clears them.
  4. D EXTI->FPR1 = 0; No. Zeros clear nothing. Line 9 stays pending and the handler runs forever.

Answer: B. FPR1 is write 1 to clear. A 1 written to a bit clears that line's pending flag and a 0 does nothing, so the plain store 1u << 9 clears line 9 and nothing else.

Both compound assignments read FPR1 first. A writes back every pending 1 and clears edges nobody has handled. C writes 0 to bit 9, so line 9 stays pending and the handler is entered again and again, and it clears the other lines as well. D writes only zeros and clears nothing.

Exam line

Pending registers are write 1 to clear. Clear with a plain store, EXTI->FPR1 = 1u << n;. |= and &= ~ read the register first and write the other lines' pending 1s back, which clears them.
