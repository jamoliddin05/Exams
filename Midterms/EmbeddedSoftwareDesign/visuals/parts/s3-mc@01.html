Question 5 · L01, What load–store buys

x86 instructions are 1 to 15 bytes long. On the Cortex-M0+ every instruction is 2 or 4 bytes, and only ldr and str touch memory. What does this load–store design buy the Cortex-M0+?

  1. AFewer instructions for the same C code, because each instruction does more workNo. Load–store needs more instructions, three for counter++ against one. That is the cost.
  2. BArithmetic instructions that take an operand straight from SRAM, so no register is needed for itNo. That is the register–memory model of the x86. Here the ALU sees registers only.
  3. CA fixed-length encoding: the decoder never has to work out how long an instruction is before it can find the next one, and every opcode goes through the same pipeline stagesCorrect. This is what the slide says the design buys.
  4. DA single uninterruptible instruction that sets one bit in a peripheral register, as the AVR's sbi didNo. The M0+ has no sbi. Setting a bit takes ldr, orrs, str.

Answer: C. Keeping memory out of arithmetic means no instruction has to carry an address and an immediate at once. So every Thumb instruction is 2 bytes, or 4 when 16 bits cannot do the job. The decoder knows where the next instruction starts from the first halfword alone, and every opcode goes through the same pipeline stages.

A 48 MHz part with no cache is built from those properties. Option A turns the price into a gain: counter++ takes three instructions here and one on the x86, with the same two bus accesses on both.

Exam line

Load–store costs instructions, not memory traffic. It buys a fixed-length encoding (Thumb: 2 or 4 bytes), a decoder that never has to ask how long an instruction is, and the same pipeline stages for every opcode. The x86 is register–memory, 1 to 15 bytes.

Question 6 · L01, tst and a missing volatile

A driver defines its own USART register struct and forgets volatile. At -Os the wait for TXE (bit 7, mask 0x80 in r0) compiles to the listing below. The first read of ISR returns 0x00000000; a few microseconds later the hardware sets TXE. What happens?

        ldr   r6, [r4, #28]    ; read USART->ISR
loop:   tst   r6, r0
        beq   loop
        str   r5, [r4, #40]    ; write USART->TDR
  1. AIt writes TDR as soon as TXE becomes 1, because tst reads ISR again on every passNo. tst compares two registers and never reads memory. The only ldr of ISR sits before the loop.
  2. BIt writes TDR at once, because tst stores r6 AND r0 in r6 and beq is taken only when that value is non-zeroNo, twice. tst keeps only the flags, and beq is taken when the result is zero (Z = 1).
  3. CIt hangs: the only ldr is outside the loop, so tst keeps testing the stale 0 in r6; Z stays 1 and beq is always takenCorrect. The loop never reads ISR again.
  4. DIt HardFaults, because tst cannot test a value that came from a peripheral registerNo. Once loaded, r6 is an ordinary register value. Nothing faults; the board just stops.

Answer: C. tst is an AND that throws the result away and keeps the flags. 0 AND 0x80 = 0, so Z = 1 and beq loop is taken. The branch goes back to tst, not to the ldr, so r6 never changes and the loop spins forever on the stale 0.

Without volatile the compiler may read ISR once and keep it in a register: the slide's "works at -O0 and hangs at -Os". With volatile, which CMSIS applies to every register as __IO, the ldr moves inside the loop, and option A becomes true.

Exam line

tst is an AND that keeps only the flags; beq is taken when the result is 0 (Z = 1). Without volatile the compiler reads a status register once, caches it in a register and loops forever: works at -O0, hangs at -Os. CMSIS __IO is volatile.

Question 7 · L01, Prologue and epilogue

A C function uses r4 and r5 and calls another function, so gcc gives it the prologue push {r4, r5, lr}. Which epilogue returns to the caller correctly?

  1. Apop {r4, r5} followed by bx lrNo. The inner bl overwrote LR, so bx lr jumps back into this function, and the saved LR word stays on the stack.
  2. Bpop {r4, r5, lr} with nothing after itNo. It restores LR but does not branch, so the core runs on into the bytes after the function.
  3. Cbx lr aloneNo. It jumps back into this function, with r4 and r5 not restored and SP 12 bytes low.
  4. Dpop {r4, r5, pc}Correct. r4 and r5 come back, and the saved LR goes straight into PC.

Answer: D. The prologue saved three words: the caller's r4 and r5, which AAPCS says a function must give back unchanged, and LR, the way back to the caller. pop {r4, r5, pc} loads all three in one instruction, and loading PC is the branch: popping into PC returns.

By the epilogue LR itself is useless, because the inner bl replaced it with an address inside this function. So A and C jump back into the function, and B restores LR but never branches. On this chip B would not even assemble: a 16-bit pop can name r0–r7 and PC, not LR.

Exam line

Non-leaf prologue push {r4, r5, lr}, epilogue pop {r4, r5, pc}: popping the saved LR into PC is the return. After an inner bl, bx lr uses the overwritten LR. AAPCS: r4–r11 are callee-saved.

Question 8 · L01, Thumb bit and little-endian

The linker map puts Reset_Handler at 0x08000190. A student writes the vector table by hand in assembly. Which four bytes must the image hold at addresses 0x08000004 to 0x08000007, the reset vector?

  1. A90 01 00 08No. The byte order is right, but the address is even: bit 0 = 0 asks for ARM state, and the chip faults on reset.
  2. B08 00 01 91No. Big-endian order. The core would read 0x91010008.
  3. C08 00 01 90No. Big-endian and even. The core would read 0x90010008.
  4. D91 01 00 08Correct. 0x08000191, lowest byte at the lowest address.

Answer: D. Every code address handed to the core has bit 0 set, the Thumb bit, so the vector is 0x08000190 | 1 = 0x08000191. The Cortex-M is little-endian: the lowest byte, 0x91, goes to the lowest address, 0x08000004, and the image holds 91 01 00 08.

A is the even address. Bit 0 = 0 asks for ARM state, which a Cortex-M does not have, so the chip faults immediately on reset. B and C store the bytes in big-endian order; read back little-endian they are 0x91010008 and 0x90010008, both even and nowhere near the code.

Exam line

A vector or function pointer is the address | 1, the Thumb bit: Reset_Handler at 0x08000190 gives the vector 0x08000191, stored little-endian as 91 01 00 08. An even vector faults on reset.
