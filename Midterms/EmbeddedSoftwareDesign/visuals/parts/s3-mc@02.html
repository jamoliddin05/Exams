Question 9 · L02, Bootstrapping

A classmate says: "Booting a microcontroller must work like booting a PC. Some firmware has to load a bootloader before my program can run." Which statement describes how the STM32C031C6 actually boots?

  1. A Like a PC, in four handoffs: boot firmware, bootloader, kernel, then main() No. That is the PC's chain. This chip has no firmware, bootloader or kernel in front of your code.
  2. B In two handoffs: the hardware runs SystemInit, and SystemInit calls main() No. SystemInit is called by Reset_Handler, which is code in your startup file.
  3. C In one link: the hardware reads two 32-bit words from the start of flash, the initial SP and the reset vector, and runs Reset_Handler; everything after that is code you can read Correct. "This chip's chain has one link. Two words, then your code."
  4. D With no handoff at all: the CPU starts executing main() at 0x08000000, the first address of flash No. The word at 0x08000000 is the initial stack pointer, a value, not an instruction.

Answer: C. Bootstrapping always starts with one fixed act by the hardware. A PC's CPU starts at a fixed address near the top of its address space and hands off four times: firmware, bootloader, kernel, your program.

This chip's chain has one link: load SP from word 0 and PC from word 1, then Reset_Handler runs and does the rest in code (copy .data, zero .bss, SystemInit, main()). It is short enough to read in full, and if one of those two words is wrong, nothing else exists to catch it.

Exam line

The only step the hardware does: read two 32-bit words from address zero of flash, the stack pointer and the reset vector, and start. A PC has four handoffs (firmware, bootloader, kernel, program). This chip's chain has one link.

Question 10 · L02, Address binding

The map file of a build says SystemCoreClock is at 0x20000000. You program the same Main.hex into two boards and press reset on each many times. Where is SystemCoreClock on each board and each run, and why?

  1. A Always at 0x20000000: the locate stage bound it at build time, and the address is burned into the image Correct. Compile-time (build-time) binding: no loader, no MMU.
  2. B It can move after each reset, because Reset_Handler works as a loader and picks a new base for .data No. That would be load-time binding. Reset_Handler copies .data to the addresses the linker already chose.
  3. C It can differ between the boards, because an MMU maps 0x20000000 to a different physical address on each No. That would be run-time binding, and this chip has no MMU.
  4. D The programmer picks a free RAM address when it writes the hex file, so each board can get a different one No. The programmer copies flash bytes to the addresses in the records. It makes no layout choices.

Answer: A. A name can be bound to its address at compile time, load time or run time. With no loader and no MMU, this chip binds at build time.

The code that uses SystemCoreClock carries 0x20000000 inside the image, so the address is the same on every board and every run until you re-link. Options B and C describe the other two moments, load time and run time, which this chip cannot use.

Exam line

Here there is no loader and no MMU, so binding happens at build time and is burned into the image. Every name has one real address, the same on every run, chosen by the locate stage from your linker script.

Question 11 · L02, Linker script LENGTH

A linker script for the STM32C031C6, which has 12 KB of SRAM, says RAM (rw) : ORIGIN = 0x20000000, LENGTH = 16K, and the stack top is ORIGIN(RAM) + LENGTH(RAM). What initial SP ends up in the image, and what happens?

  1. A 0x20003000, and the program runs normally, because the hardware limits SP to the real end of RAM No. The hardware loads word 0 into SP as it is. Nothing checks it.
  2. B 0x20004000: the build succeeds, but the stack starts above the real 12 KB, so the program fails at run time Correct. 16K = 0x4000. The linker trusts your numbers, and the failure comes later.
  3. C 0x20004000, but the linker stops with an error because the chip has only 12 KB, so no image is produced No. The linker knows nothing about your chip. The MEMORY block is all it knows.
  4. D 0x20010000, because 16K is 0x10000, and the program fails at run time No. 0x10000 = 65536 = 64K. 16K is 0x4000.

Answer: B. 16K = 16 × 1024 = 16384 = 0x4000, so the stack top is 0x20000000 + 0x4000 = 0x20004000. Real SRAM ends at 0x20002FFF (12K = 0x3000).

The linker knows nothing about your chip, so the build succeeds and even reports a smaller RAM percentage. In the slide's words, the failure arrives later, as a stack that walks off the end of memory: the first push writes to memory that does not exist.

Exam line

The MEMORY numbers come from the datasheet: FLASH 32K at 0x08000000, RAM 12K at 0x20000000. Get LENGTH wrong and the build succeeds; the failure arrives later, as a stack that quietly walks off the end of memory.
