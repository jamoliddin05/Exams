Question 18 · L05, AFR[1] clear-then-set

PA10 must carry alternate function 1 (AF1), and its MODER field already holds 10. Which line writes AF1 into PA10's field and leaves every other pin's AF number as it was?

  1. A GPIOA->AFR[1] = (GPIOA->AFR[1] & ~(0xFu << 8)) | (1u << 8); Correct. PA10 is in AFR[10 / 8] = AFR[1], at bits 4 × 2 + 3 : 4 × 2 = 11:8.
  2. B GPIOA->AFR[0] = (GPIOA->AFR[0] & ~(0xFu << 8)) | (1u << 8); No. AFR[0] holds pins 0 to 7, and its bits 11:8 are PA2's field.
  3. C GPIOA->AFR[1] = (GPIOA->AFR[1] & ~(3u << 20)) | (1u << 20); No. That is the 2-bit rule, 2n = 20. Bits 21:20 of AFR[1] are inside PA13's field, a debug pin.
  4. D GPIOA->AFR[1] = (GPIOA->AFR[1] & ~(0xFu << 10)) | (1u << 10); No. It shifts by n. Bits 13:10 straddle PA11 and PA10, and the 1 at bit 10 makes AF4.

Answer: A. AFR gives each pin 4 bits, so it takes two registers, AFR[0] for pins 0–7 and AFR[1] for pins 8–15. PA10 is in AFR[10 / 8] = AFR[1], and its field starts at bit 4 × (10 mod 8) = 8, so it is bits 11:8.

The mask is 0xFu << 8 = 0x00000F00 and AF1 is 1u << 8 = 0x00000100. B has the right bits in the wrong register, C uses the 2-bit MODER rule, and D shifts by the pin number as for IDR.

Exam line

Pin n's AF number is in AFR[n / 8], bits 4(n mod 8)+3 : 4(n mod 8), one hex digit per pin. PA10 is AFR[1] bits 11:8, so clear with & ~(0xFu << 8) and set AF1 with | (1u << 8).

Question 19 · L05, The LED bar in one BSRR write

The LED bar on PB7–PB0 is written with the line below. What value is written to BSRR when leds is 0x0C?

GPIOB->BSRR = ((uint32_t)(uint8_t)~leds << 16) | leds;
  1. A 0x000C00F3 No. The halves are swapped. It sets the six LEDs that should go off and resets PB3 and PB2.
  2. B 0xFFF3000C No. That is the value without the (uint8_t) cast. Its 1s in bits 31:24 also reset PB15–PB8.
  3. C 0x0000000C No. That is leds alone. PB3 and PB2 go on, and the other six LEDs keep what they showed.
  4. D 0x00F3000C Correct. The set half 0x000C lights PB3 and PB2, and the reset half 0x00F3 turns off the other six.

Answer: D. The low half is leds = 0x000C, bits 3 and 2, which sets PB3 and PB2. ~leds cut to 8 bits by the cast is 0xF3 = 1111 0011, and << 16 moves it into bits 23:16, the reset bits of PB7–PB4, PB1 and PB0.

Bits 31:24 stay 0, so PB15–PB8 are untouched, and the OR gives 0x00F3000C. One store lights the LEDs that should be on and turns off the rest, so the bar shows exactly leds.

Exam line

In the bar line, the (uint8_t) cast keeps ~leds to 8 bits. For leds = 0x0C the set half is 0x000C, the reset half 0x00F3, and BSRR = 0x00F3000C. PB15–PB8 see only 0s and are untouched.

Question 20 · L05, IRQ to vector address

TIM3's interrupt is IRQ 16, and the vector table starts at 0x08000000. At which address does the CPU read TIM3's vector?

  1. A 0x08000080 Correct. Vector 16 + 16 = 32, and 32 × 4 = 128 = 0x80.
  2. B 0x08000040 No. 16 × 4 = 0x40 forgets the 16 core vectors. That slot is vector 16, IRQ 0.
  3. C 0x08000020 No. 32 = 0x20 counts vectors as bytes. Each vector is 4 bytes.
  4. D 0x08000081 No. Bit 0 is set in the word stored in the vector, the handler's address. The vector itself starts at a multiple of 4.

Answer: A. The first 16 vectors belong to the core (initial SP, Reset, NMI, HardFault, … SysTick), so IRQ n is vector 16 + n, and IRQ 16 is vector 32. Each vector is a 4-byte word, so vector 32 starts 32 × 4 = 128 = 0x80 bytes into the table, at 0x08000080.

By hand, × 4 is two left shifts, and 0010 0000 becomes 1000 0000. The Thumb bit belongs to the word read from 0x08000080, never to the address of the slot.

Exam line

Vector address = 0x08000000 + (16 + IRQ) × 4. IRQ 16 is vector 32 at 0x08000080. The Thumb bit is in the word stored there, never in the slot's address.

Question 21 · L05, Silent failure: the handler name

Button B's handler is written as below. Everything else in button B's setup is right, and the build reports zero warnings. What happens at the first press of button B?

void EXTI0_1_IRQhandler(void)          /* lower-case h */
{
    uint32_t mask = 1u << 1;
    if ((EXTI->RPR1 | EXTI->FPR1) & mask) {
        EXTI->RPR1 = mask;
        EXTI->FPR1 = mask;
        b_edges++;
    }
}
  1. A The handler runs as usual, because the linker matches symbol names without regard to case No. C names are case-sensitive, so IRQhandler and IRQHandler are two symbols.
  2. B The CPU jumps to Default_Handler, an infinite loop, and the board hangs Correct. Vector 21 still holds the weak placeholder, which points at Default_Handler.
  3. C Nothing visible happens; the edge stays latched in FPR1 and main() keeps running No. That is a masked line, IMR1 not set or the NVIC not enabled. Here the IRQ is taken.
  4. D The handler is entered again and again, because its pending bit is never cleared No. That needs the handler to run, and the misspelt function never runs at all.

Answer: B. startup.c fills vector 21 with a weak EXTI0_1_IRQHandler that points at Default_Handler, an infinite loop. Only a function with exactly that name is a strong symbol that replaces it at link time. EXTI0_1_IRQhandler is another name, nothing refers to it, and the linker deletes it as dead code with no warning.

At the first press the edge passes EXTI and the NVIC as usual. The CPU reads vector 21, jumps into Default_Handler and stays there, so the heartbeat stops and the serial port goes quiet.

Exam line

The handler's name is the only connection to its vector. A misspelt name builds with zero warnings, the weak placeholder keeps vector 21 on Default_Handler, and the first press hangs the board. Check with nm: your handler must show T.

Question 22 · L05, Push-pull vs open-drain

Two chips must share one wire, and either one may pull it low at any moment, as on I²C's data line. How should each chip's pin be set up?

  1. A Push-pull (OTYPER = 0) on both, so each chip drives the wire firmly high and low No. If one drives high while the other drives low, 3.3 V meets GND through two transistors, a short.
  2. B Push-pull with OSPEEDR = 11, so the faster edges let the right chip win No. OSPEEDR sets the slope of each edge. The short is the same as in A.
  3. C Open-drain (OTYPER = 1) on both, with a pull-up resistor on the wire Correct. Each pin pulls low or lets go, the resistor makes the high, and the wire is 1 only when both let go.
  4. D Open-drain (OTYPER = 1) on both, with no resistor, since each chip drives the high itself No. An open-drain pin cannot drive high. With both let go, the wire floats.

Answer: C. Open-drain switches the P-MOS off for good, so the pin can only pull low through its N-MOS or let go, and the pull-up resistor makes the high. The worst case is both chips pulling low at once, which is harmless, and the wire reads 1 only when every chip lets go. That is a wired-AND, the way I²C shares its two wires.

With push-pull (A, B), one chip driving high while the other drives low joins 3.3 V to GND through two transistors. OSPEEDR changes only the slope of each edge. Without the resistor (D) nothing makes the high, and the released wire floats.

Exam line

Open-drain (OTYPER = 1) pulls low or lets go, and a pull-up makes the high, so chips can share a wire as a wired-AND, as on I²C. Two push-pull outputs driving opposite levels short 3.3 V to GND. OSPEEDR is only the edge slope.
