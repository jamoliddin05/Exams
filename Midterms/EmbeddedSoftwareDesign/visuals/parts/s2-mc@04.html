Question 15 · L04, .data placement

int limit = 50; is a global that the program changes at run time, and it must hold 50 again after every power-on. Reset_Handler copies .data from _sidata, defined in link.ld as _sidata = LOADADDR(.data);. Which link.ld line places .data correctly?

  1. A .data : { _sdata = .; *(.data*) _edata = .; } >FLASH No. limit would live in FLASH, which is (rx), so an ordinary store cannot change it.
  2. B .data : { _sdata = .; *(.data*) _edata = .; } >RAM No. Nothing is stored in FLASH, so 50 is gone after power-off, and LOADADDR is the RAM address itself.
  3. C .data : { _sdata = .; *(.data*) _edata = .; } >FLASH AT> RAM No. This is backwards. It would run from FLASH and be stored in RAM, which is empty at reset.
  4. D .data : { _sdata = .; *(.data*) _edata = .; } >RAM AT> FLASH Correct. Lives in RAM, stored in FLASH. LOADADDR(.data) is the FLASH copy.

Answer: D. A global with an initial value needs two addresses. The value must survive power-off, so it is stored in FLASH. The variable must be writable, so it lives in RAM. >RAM AT> FLASH is the syntax for those two addresses. The run address (VMA) is in RAM, and the load address (LMA) is in FLASH.

LOADADDR(.data) returns the load address, so _sidata points at the stored 50 in FLASH, and Reset_Handler's first loop copies it to _sdata in RAM before main(). On the next power-on the copy runs again and limit is 50 once more.

Exam line

>RAM AT> FLASH means the section lives in RAM and is stored in FLASH. LOADADDR(.data) gives the FLASH copy, _sidata, and Reset_Handler copies it to _sdata before main().

Question 16 · L04, Memory usage

arm-none-eabi-size -A prints the sections below for a build, and there are no others. How much FLASH and how much RAM does the linker report as used?

section               size
.isr_vector            180
.text                 4000
.rodata                800
.data                  120
.bss                   400
._user_heap_stack     1536
  1. A FLASH 4980 B, RAM 2056 B No. 4980 leaves out the FLASH copy of .data.
  2. B FLASH 5500 B, RAM 2056 B No. 5500 also counts .bss, which gets no FLASH at all, only a size.
  3. C FLASH 5100 B, RAM 2056 B Correct. 180 + 4000 + 800 + 120 = 5100 and 120 + 400 + 1536 = 2056.
  4. D FLASH 5100 B, RAM 520 B No. 520 leaves out the 1536-byte heap and stack reservation.

Answer: C. FLASH holds the vector table, .text, .rodata and the stored copy of .data: 180 + 4000 + 800 + 120 = 5100 bytes. RAM holds .data, .bss and the heap and stack reservation: 120 + 400 + 1536 = 2056 bytes.

.data is counted twice, once at its RAM address and once at its FLASH load address, so it costs both. .bss is all zeros, so it gets no FLASH, only a size, and the startup code writes the zeros at run time.

Exam line

FLASH used = vectors + .text + .rodata + .data again. RAM used = .data + .bss + the heap and stack reservation. .data costs you both, and .bss costs no FLASH at all.

Question 17 · L04, Weak alias

startup.c declares the line below, and nm shows Default_Handler at 0x08000678. A student enables the TIM3 interrupt and defines void TIM3_IRQhandler(void) { ... } in main.c. The build has no errors and no warnings. Which value does TIM3's entry in the vector table hold?

void TIM3_IRQHandler(void) __attribute__((weak, alias("Default_Handler")));
  1. A 0x08000679, the address of Default_Handler with the Thumb bit set Correct. The misspelt function overrides nothing, so the weak alias stays.
  2. B 0x08000678, the address of Default_Handler No. Every handler entry has bit 0 set, the Thumb bit. An even entry faults on the first instruction.
  3. C 0x00000000, because no TIM3_IRQHandler was defined No. The weak alias defines TIM3_IRQHandler as Default_Handler, so the slot is never empty.
  4. D The address of the student's TIM3_IRQhandler plus 1, because it is the only TIM3 handler in the program No. The linker matches names exactly. IRQhandler is not IRQHandler.

Answer: A. A weak symbol is a default that any ordinary definition of the same name overrides at link time. The name is the registration. TIM3_IRQhandler has a lower-case h, so it is a different name, and it overrides nothing.

The table therefore keeps the weak alias, Default_Handler at 0x08000678, stored with the Thumb bit as 0x08000679. There is no error and no warning. The first TIM3 interrupt runs Default_Handler's for (;;), and the board hangs.

Exam line

The name is the registration. A misspelt handler overrides nothing, the weak Default_Handler stays in the table, and the first interrupt hangs the board with no error and no warning.
