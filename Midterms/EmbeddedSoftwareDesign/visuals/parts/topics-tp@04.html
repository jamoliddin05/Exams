Startup and the Linker Script: Building the Ground You Stand On

The code that runs before main(): the vector table, Reset_Handler, the .data copy, the .bss zero and the 12 → 48 MHz clock, plus the link.ld that decides where every byte lives. It is the first lesson with code you build and run. It builds on lesson 00's memory map, lesson 01's Thumb bit and addressing modes, and lesson 02's rule that something must build the C environment before main().

1. The board and its pins (pin map slides)

The deck opens with the pins of the Nucleo-C031C6: STM32C031C6, Cortex-M0+, 48 MHz, 32 KB flash, 12 KB RAM. The outer double rows are ST's morpho headers, which reach every pin of the chip. The inner single rows are the Arduino header (A0–A5, D0–D15). Inside the chip a pin is one bit position in its port's registers.

  • PA13 and PA14 are SWD, the debug pins. PB0–PB7 are the only pins this lesson chose. The board fixed the other three.

2. main() is not where your program starts (slides 1–2)

On a laptop the operating system quietly does four jobs on the way in, and "you never see any of it". On this chip nobody does them, "unless you write it". The lesson asks: "what are those four jobs, who does them here, and what exactly breaks when one of them is missing?"

3. The memory map with this chip's numbers (slide 3)

  • "You have 32 KB and 12 KB inside a 4 GB space." Almost all of it is nothing. "Addressability is not memory": reading an unmapped address is a fault, not a zero.
  • "link.ld's MEMORY block is two rows of this picture", and nothing else: FLASH at 0x08000000 (32 KB, to 0x08007FFF) and SRAM at 0x20000000 (12 KB, to 0x20002FFF).
  • GPIO is at 0x50000000, not 0x40000000. On the STM32C0 the I/O ports sit on their own port (IOPORT), outside the peripheral region. Code copied from an F1 or F4 tutorial has the wrong address, "and the chip will not tell you".
  • FLASH is aliased at 0x00000000 on reset. The core region (SysTick 0xE000E010, NVIC 0xE000E100, SCB 0xE000ED00) is ARM's, identical on every Cortex-M. Every number was checked against ST's CMSIS header.

4. The I/O map: GPIOA->MODER is an address (slide 4)

"A register is an address with a side effect." There is no I/O instruction on this machine and no I/O address space: peripherals are reached by ordinary loads and stores.

  • CMSIS, the Common Microcontroller Software Interface Standard, is ARM's vendor-neutral header set for Cortex-M. The course uses ARM's core header core_cm0plus.h (NVIC, SysTick, SCB) and ST's device header stm32c031xx.h (every peripheral of this part).
  • "CMSIS is headers, not a library." Nothing is linked and no function is called. It is #defines and struct declarations that put names on the addresses in the reference manual. It is not ST's HAL, which is a real library (lesson 11 compares the two).
  • GPIOA is a pointer to a struct pinned at a fixed address, so -> is nothing but base + offset, computed at compile time.

5. Every register on one page: RCC, GPIO, USART2 (slides 4a–4c)

  • RCC, Reset and Clock Control, at 0x40021000. The gates IOPENR, AHBENR, APBENR1 and APBENR2 have one bit per peripheral, and 0 means "unclocked and silently deaf". IOPENR: GPIOAEN bit 0, GPIOBEN bit 1. APBENR1: USART2EN bit 17 (also TIM3, I2C1, PWR). APBENR2: TIM1, SPI1, USART1, ADC. The sources CR and CFGR set the chip clock. Enable the gate first, always: led_init() sets its gate before anything else.
  • GPIO: every port is the same eleven words, GPIOA at 0x50000000 and GPIOB at 0x50000400. Configuration registers (MODER, OTYPER, OSPEEDR, PUPDR, AFR[], LCKR) say what a pin is, written once at start-up. Data registers (IDR, ODR, BSRR, BRR) say what it does, in the main loop.
  • The UART pins: MODER = 10 says a peripheral drives this pin, and AFR[0] = 1 says which one, AF1 = USART2 on PA2 and PA3. "Neither alone is enough."
  • USART2 at 0x40004400: retarget.c uses four of its twelve registers. CR1 (UE, TE, RE), BRR (417), ISR (poll TXE_TXFNF) and TDR (the byte to send).
  • Every address on these slides was verified by compiling _Static_assert((uintptr_t)&RCC->IOPENR == 0x40021034UL, ...) against ST's header.

6. Reset and the vector table (slides 5–7)

On AVR, reset jumps to address 0 and the bootstrap must be assembly, because the stack pointer is not set up yet and C cannot run without a stack. Cortex-M "does it differently, and better". The core itself reads the first two words of memory before fetching a single instruction: word 0 into SP, word 1 into PC. So the very first instruction runs with a valid stack, which is why Reset_Handler can be written in C.

The table the hardware reads is, in C, an array of function pointers that the linker places at the very start of FLASH:

__attribute__((section(".isr_vector"), used))
void (* const vectors[])(void) = {
    (void (*)(void))&_estack,       /*  0  initial stack pointer  */
    Reset_Handler,                  /*  1  reset                  */
    NMI_Handler,                    /*  2                         */
    HardFault_Handler,              /*  3                         */
    0, 0, 0, 0, 0, 0, 0,            /*  4-10 reserved             */
    SVC_Handler,                    /* 11                         */
    0, 0,
    PendSV_Handler,                 /* 14                         */
    SysTick_Handler,                /* 15                         */
    /* then the peripheral interrupts, IRQ0 upward ... */
  • section(".isr_vector") puts the array in a section of its own, so link.ld can pin it to 0x08000000 instead of letting it land wherever.
  • used stops the compiler deleting an array that no C code ever reads. Nothing in your program mentions vectors. Only the hardware does.
  • const puts it in FLASH. Drop it and the table spends 180 bytes of the 12 KB RAM on data that never changes.
  • Entry 0 is not a function pointer. It is the initial stack pointer, "wearing a cast so the whole table can be one array".
  • Entries 0–15 belong to the core: 0 initial SP, 1 Reset, 2 NMI, 3 HardFault, 11 SVCall, 14 PendSV, 15 SysTick. Peripheral IRQ n is vector 16 + n, at 0x08000000 + (16 + n) × 4. Here 16 + 29 IRQs = 45 words = 180 bytes, the size of .isr_vector.

Slide 7 reads that table back out of this lesson's own Main.hex. Record 2 is :10000000 00300020C50600087906000879060008 BF. ARM is little-endian, so each group of four bytes reads right to left.

BytesValueMeaning
00 30 00 200x20003000initial SP, the top of RAM
C5 06 00 080x080006C5Reset_Handler

79 06 00 080x08000679HardFault_Handler
  • 0x20003000 is not a number someone typed. RAM starts at 0x20000000 and has 12 KB, and 0x20000000 + 0x3000 is exactly the top. The linker computed it, and the stack grows downward from it.
  • Every handler address is odd. nm reports Reset_Handler at 0x080006C4. The low bit is the Thumb bit from lesson 01, "this target is Thumb code", not part of the address. An even entry faults on the first instruction.
  • Words 2 and 3 are identical because NMI_Handler and HardFault_Handler are both weak aliases of one Default_Handler (at 0x08000678).

7. Weak aliases, and the trap that costs an afternoon (slide 8)

#define WEAK_ALIAS __attribute__((weak, alias("Default_Handler")))

void TIM3_IRQHandler(void)     WEAK_ALIAS;     /* startup.c: the default       */
void USART2_IRQHandler(void)   WEAK_ALIAS;

void TIM3_IRQHandler(void) { /* ... */ }       /* strong: wins at link time    */
void Default_Handler(void) { for (;;) { } }    /* parks the core               */
  • A weak symbol is "a default that any ordinary definition overrides". A lesson that wants the timer interrupt writes a plain C function with exactly that name. No ISR() macro, no vector number, nothing to register: "The name is the registration."
  • Default_Handler is an infinite loop. It parks the core instead of returning, so a debugger can attach and read IPSR.
  • The trap: TIM3_IRQhandler, one letter wrong. It "compiles. links. runs." You have defined a function nobody calls, and the weak default still sits in the vector table. The first TIM3 interrupt parks the board in Default_Handler. No error, no warning, "no symptom except silence". The linker even deletes the misspelled function as dead code.
  • "The single most expensive typo on this architecture." When an interrupt "does not fire", check the spelling first: nm Main.elf should list your handler as T (yours), not W (weak).

8. Four kinds of bytes, and why .data has two addresses (slides 9–10)

The compiler sorts every byte of the program into a section. Four of them account for almost everything.

SectionHoldsLives inAt resetThis lesson's witness
.textyour codeFLASH onlyruns in placeReset_Handler, main()
.rodataconst dataFLASH onlyread in placeconst uint32_t rodata_witness = 0x5AFEu;
.datainitialised globalsFLASH and RAMmust be copiedvolatile uint32_t data_witness = 0x00C0FFEEu;
.bsszeroed globalsRAM onlymust be zeroedbss_witness = 0u; static uint32_t frame_count;
  • "The two on the left are finished when the chip is programmed. The two on the right are promises nothing has kept yet." C promises that int counter = 0; is zero and int magic = 0xC0FFEE; holds that value when main() begins. "On this chip you are the one who keeps them."
  • A .data value must survive power-off, so it is stored in FLASH. The variable must be writable, so it lives in RAM. It needs two addresses: the load address (LMA) where it is stored, _sidata = 0x08001D64, and the virtual address (VMA) where it runs, 0x20000000 to 0x20000064 (100 bytes). For .text the two are the same.
  • .bss has the opposite shape. Storing hundreds of identical zeros would waste FLASH, so .bss gets no FLASH at all, only a size (372 bytes here). Startup writes the zeros at run time.

9. Reset_Handler, in full (slide 11)

void Reset_Handler(void)
{
    uint32_t *src, *dst;

    /* 1. copy .data from FLASH into RAM */
    src = &_sidata;
    for (dst = &_sdata; dst < &_edata; ) { *dst++ = *src++; }

    /* 2. zero .bss */
    for (dst = &_sbss; dst < &_ebss; ) { *dst++ = 0; }

    SystemInit();          /* 3. clock: 12 MHz -> 48 MHz                 */
    __libc_init_array();   /* 4. C++ ctors, __attribute__((constructor)) */

    (void)main();
    for (;;) { }           /* main() must not return — but if it does    */
}
  • "Two memcpy-shaped loops over addresses the linker chose. That is the entire mystery of what happens before main."
  • The order is copy .data, zero .bss, SystemInit(), __libc_init_array(), main(). SystemCoreClock is an initialised global, so it sits in .data. The copy has to come before SystemInit(), or it would write 12000000 back over 48000000.
  • On a desktop a returning main() ends the process. Here there is nothing to exit to, and a bare return would run into whatever bytes follow in FLASH. "The infinite loop is a wall."

10. Linker symbols are addresses, not variables (slide 12)

extern uint32_t _sdata, _edata;

for (dst = &_sdata; dst < &_edata; ) { ... }   /* correct  */
uint32_t n = _edata - _sdata;                  /* WRONG    */
You writeYou get
&_sdatathe address the linker chose: what you want
_sdatathe four bytes that happen to live at that address
  • The linker creates no storage for _sdata. It creates a symbol whose value is the address. extern uint32_t _sdata; is "a polite lie told to the compiler" so that &_sdata has a type. Reading _sdata itself compiles cleanly and returns garbage.
  • Rule: "a linker symbol is only ever used with &. If you see one without an ampersand, it is a bug." Main.c uses eight of them, all with &, and prints every one.
  • A size in bytes is a difference of addresses as integers: (uintptr_t)&_edata − (uintptr_t)&_sdata = 100. On uint32_t pointers, &_edata − &_sdata counts words: 25.

11. link.ld: the map, the sections, and where the memory went (slides 13–15)

The first half of the linker script says what memory exists. It is slide 3's picture, transcribed:

MEMORY
{
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 32K
  RAM   (rw)  : ORIGIN = 0x20000000, LENGTH = 12K
}

_estack = ORIGIN(RAM) + LENGTH(RAM);     /* 0x20000000 + 12 × 1024 = 0x20003000 */
  • FLASH is at 0x08000000, not at 0: the low addresses are the code-region alias. RAM at 0x20000000 is the same on every Cortex-M; "that address is architectural, not ST's choice".
  • 32K and 12K belong to this exact part number, a C031C6. Change the part and this line changes with it.
  • _estack is computed, not typed. That is why 0x20003000 in the vector table is trustworthy: "nobody could have mistyped it."

The second half assigns each section to a region. Three lines carry the whole idea:

.text   : { *(.text*) }   >FLASH

.data   : {
    _sdata = .;
    *(.data*)
    _edata = .;
}  >RAM AT> FLASH          /*  <-- lives in RAM, stored in FLASH  */

_sidata = LOADADDR(.data); /*  <-- where it was stored            */

.bss    : {
    _sbss = .;  *(.bss*) *(COMMON);  _ebss = .;
}  >RAM                    /*  no AT> — nothing to store          */
  • >RAM AT> FLASH is the syntax for the two addresses of .data, and LOADADDR() is how startup finds the FLASH copy. "These three lines are why .data works."
  • . is the location counter, "the address I have reached so far". Assigning it to a symbol, as in _sdata = .;, is how every boundary marker is made. "The dot is the linker's entire working memory."
  • In the full file .isr_vector comes first, so it lands at 0x08000000. KEEP() protects it from --gc-sections, which deletes unreferenced sections; no C code references the table. The last section, ._user_heap_stack, reserves 0x200 + 0x400 = 1536 bytes and marks the heap start with PROVIDE(end = .).

The linker's own summary, printed at every build: FLASH 7624 B of 32 KB (23.27%), RAM 2008 B of 12 KB (16.34%). Both sums teach something:

RAM   = .data + .bss + heap/stack reservation
      = 100 + 372 + 1536                     = 2008 B
FLASH = .isr_vector + .text + .rodata + 4 + 4 + .data again
      = 180 + 5684 + 1652 + 4 + 4 + 100      = 7624 B
  • The heap and stack reservation is three quarters of the RAM use, "and you have not written a real program yet".
  • The 100 in the FLASH sum is .data counted a second time, at its load address. ".data costs you both." A large initialised array is the most expensive thing you can declare on a part this size.
  • Prefer const: .rodata costs FLASH only, and .bss costs no FLASH at all.
  • The slide's size -A table prints 0x20000218 for ._user_heap_stack. The sums above and the serial report (heap at 0x200001D8) place it at 0x200001D8, which the figure uses.

12. The clock: 48 MHz in one register write (slide 16)

The last of the four startup jobs. The STM32C0 wakes on its 48 MHz internal oscillator, HSI48, divided by four: 12 MHz.

void SystemInit(void)
{
    FLASH->ACR = (FLASH->ACR & ~FLASH_ACR_LATENCY) | FLASH_ACR_LATENCY_0;
    while ((FLASH->ACR & FLASH_ACR_LATENCY) != FLASH_ACR_LATENCY_0) { }

    RCC->CR &= ~RCC_CR_HSIDIV;          /* divide by 1 -> 48 MHz */
    while (!(RCC->CR & RCC_CR_HSIRDY)) { }

    SystemCoreClock = 48000000UL;
}
  • FLASH->ACR (0x40022000) LATENCY, bits 2:0, is set to one wait state, and the code waits until it reads back. RCC->CR HSIDIV, bits 13:11 (mask 0x3800), is cleared to divide by 1; then the code polls HSIRDY, bit 10.
  • "The order is not negotiable." Flash memory cannot be read as fast as the CPU runs at 48 MHz, so it needs one wait state. Raise the clock first and the CPU fetches an instruction that is not ready yet: the part hangs with no error, "somewhere that has nothing to do with your bug".
  • The rule for every clock change: "wait states go up before the frequency, and come down after it."
  • "The gentlest clock setup in the STM32 family": no PLL, no lock bit to poll, no source switch. The F446RE later in the course needs all three.

13. printf needs somewhere to print (slide 17)

printf lives in the C library, and "the C library has never heard of a UART". It calls _write() and expects the system to provide one. On a laptop the OS does. Here retarget.c does, in nine lines:

int _write(int fd, const char *buf, int len)
{
    (void)fd;
    for (int i = 0; i < len; i++) {
        if (buf[i] == '\n') { uart2_putc('\r'); }
        uart2_putc(buf[i]);
    }
    return len;
}
  • That one function is the entire bridge between <stdio.h> and the hardware. Implement it and printf, puts, putchar and fprintf all work at once.
  • uart2_putc() waits while ISR's TXE_TXFNF says the transmit register is still full, then stores the byte in TDR.
  • The AVR edition hand-wrote fifteen formatters to fit a 4 KB part. Here newlib-nano's printf costs about 1.4 KB of 32 KB, so this edition uses the standard library.
  • _sbrk(), in the same file, hands malloc the gap between .bss and the stack, starting at end = 0x200001D8. printf allocates its buffer there. "Get _sbrk wrong and printf prints nothing": a silent board running a perfectly good program.
BRR = (f + baud/2) / baud = (48 000 000 + 57 600) / 115 200 = 417 = 0x01A1   (rounded to nearest)
BRR comes from SystemCoreClock: right only if the chip really runs at 48 MHz.
Chip still at 12 MHz with BRR = 417:  12 000 000 / 417 ≈ 28 777 baud, not 115 200

14. The board you are simulating, and what you should see (slides 18–19)

  • Everything to the end of the course runs on the ST Nucleo-C031C6, in the browser in Wokwi (part board-st-nucleo-c031c6). The real board's manual is UM2953.
  • ledbar_init() writes 01 (output) into the eight MODER fields of PB0–PB7. After that each frame of a pattern is one byte written to GPIOB->ODR, bit n = PBn (Figure 3).
  • A Wokwi wire names its pin by the string in Wokwi's board file, not the datasheet name. led0 is on nucleo:PB0.1, because PB0 reaches two header positions and plain PB0 does not exist. Check the Board pins page before adding a wire.
  • Wokwi does not implement DMA, RTC, IWDG, PWR, SYSCFG and DBG, and I²C and SPI are master-only. That is why the EXTI lesson works here: on an STM32F4 the interrupt pin is chosen in SYSCFG->EXTICR[], while the STM32C0 has it in EXTI->EXTICR[]. It is also why the low-power lesson moves to another simulator: PWR is not modelled.
  • "A simulator is an instrument, and every instrument has a stated range."

Exam focus
  • Bytes 00 30 00 20 C5 06 00 08 at 0x08000000: SP = 0x20003000, PC = 0x080006C5, and Reset_Handler is at 0x080006C4 (bit 0 is the Thumb bit). An even vector entry faults.
  • On reset the core loads SP from word 0 and PC from word 1 before any instruction, so Reset_Handler can be C (on AVR it could not).
  • IRQ n is vector 16 + n at 0x08000000 + 4(16 + n): TIM3 (IRQ16) → 0x08000080, IRQ7 → 0x0800005C, USART2 (IRQ28, the last) → 0x080000B0, then .text at 0x080000B4.
  • _estack = ORIGIN(RAM) + LENGTH(RAM): 12K → 0x20003000, 8K → 0x20002000.
  • const int t[4] = {1}; → .rodata, FLASH only. int t[4] = {1}; → .data, FLASH and RAM. int t[4]; → .bss, RAM only.
  • FLASH used = 180 + 5684 + 1652 + 4 + 4 + 100 = 7624 B, because .data counts twice. RAM used = 100 + 372 + 1536 = 2008 B.
  • Reset_Handler order: copy .data, zero .bss, SystemInit(), __libc_init_array(), main(), then for(;;).
  • void TIM3_IRQhandler(void) {…} compiles, links and runs; the weak Default_Handler stays in the table and the interrupt parks the board. nm shows T for yours, W for weak.
  • A linker symbol is used only with &: _edata − _sdata reads memory (garbage); (uintptr_t)&_edata − (uintptr_t)&_sdata = 100.
  • >RAM AT> FLASH: lives in RAM, stored in FLASH; _sidata = LOADADDR(.data) = 0x08001D64. The dot is the location counter.
  • Clock: reset is HSI48 ÷ 4 = 12 MHz. Set LATENCY = 1 first, then clear HSIDIV (bits 13:11) and poll HSIRDY (bit 10). Wrong order: the part hangs with no error.
  • GPIOA->ODR = 0x50000000 + 0x14 = 0x50000014; GPIOB->ODR = 0x50000414. GPIO is at 0x5…, not 0x4…. CMSIS is headers, not a library.
  • Gates: IOPENR GPIOAEN bit 0, GPIOBEN bit 1 (0x3); APBENR1 USART2EN bit 17 = 0x00020000. A peripheral with no clock reads 0 and ignores writes.
  • BRR = (48 000 000 + 57 600) / 115 200 = 417 = 0x1A1. USART2 CR1 = UE | RE | TE = 0xD. printf needs _write(); a wrong _sbrk prints nothing.
  • Moving .isr_vector after .text: 0 errors, 0 warnings, same sizes, and the chip cannot start. 2K RAM builds at 98.05% but is unsafe; 1K fails, overflowed by 984 bytes.
