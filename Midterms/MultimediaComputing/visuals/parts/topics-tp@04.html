Lossless Coding from Zero

How to store the same information in fewer bits and get every bit back. The lecture first measures how much information a source really holds (entropy), then builds codes that come close to that limit: run-length coding, Shannon-Fano, Huffman and the LZW dictionary. It starts from PCM (Lecture 3), the bits a sound becomes after sampling and quantization.

Words you need

Symbol and alphabet

One item of the data: a letter, a gray level, a quantized sample. The alphabet S = {s₁, …, sₙ} is the set of the n different symbols.

Codeword

The bits written for one symbol. A fixed-length code gives every symbol the same number of bits. A variable-length code (VLC) gives frequent symbols fewer.

Lossless and lossy

Lossless: decoding gives back exactly the original. Lossy: only a close approximation comes back.

Compression ratio

B₀ / B₁, bits before compression divided by bits after. A ratio of 2 means the data became half as big.

Probability pᵢ

How often symbol sᵢ occurs: its count divided by the total. In HELLO, p(L) = 2/5 = 0.4.

Self-information

log₂(1/pᵢ) bits, the information in one sᵢ, "the number of bits needed to encode sᵢ". Rare symbols carry more.

Entropy η

The average self-information, η = Σ pᵢ log₂(1/pᵢ), in bits per symbol. No lossless code can average fewer bits.

Average length l̄

l̄ = Σ pᵢ lᵢ, with lᵢ the length of sᵢ's codeword. Efficiency = η / l̄, at most 1.

Prefix code

No codeword is the start of another, so a bitstream splits into codewords in only one way.

Dictionary

A numbered table of strings that encoder and decoder build the same way. LZW sends the number instead of the string.

3. Predict, then send only the error: DPCM (slides 2, 6)

Neighbouring samples are close. Send how far each sample is from a guess made from earlier samples. Those numbers are small and cluster around 0, so a variable-length code gives them short codewords. The deck lists differential coding, lossless predictive coding and DPCM on slide 2 but only slide 6 says how: "predict the next signal from previous ones and transmit the prediction error".   • The decoder only has f̃. So the encoder predicts from f̃ too, and both sides make the same prediction. Each sample then carries only its own quantization error.

4. Compression, lossless and lossy, compression ratio (slides 10–11)

  • "Compression: the process of coding that will effectively reduce the total number of bits needed to represent certain information." Fig. 7.1: input data, encoder, storage or networks, decoder, output data.
  • "If the compression and decompression processes induce no information loss, then the compression scheme is lossless; otherwise, it is lossy."
  • Lossless: run-length, Shannon-Fano, Huffman, LZW, PNG. Lossy: JPEG, MP3 (Lecture 5). (class remark: JPG lossy, PNG lossless)

compression ratio = B₀ / B₁ B₀ = bits before compression, B₁ = bits after

  • A codec should have "a compression ratio much larger than 1.0". Higher is better "as long as it is computationally feasible".
  • The run-length and LZW examples on the slides count symbols, not bits. Say "in symbols" when you do that.
HELLO in 8-bit ASCII:  B₀ = 5 × 8 = 40 bits
HELLO in Huffman code: B₁ = 10 bits            (section 8)
compression ratio      = 40 / 10 = 4.0

5. Entropy: the fewest bits the information needs (slides 12–13)

A symbol that almost always occurs tells you little when it arrives. A rare one tells you a lot. Shannon measured this in bits as log₂(1/p). Entropy is its average over the source.

η = H(S) = Σ pᵢ log₂(1/pᵢ) = −Σ pᵢ log₂ pᵢ bits per symbol (7.2), (7.3)

  • log₂(1/pᵢ) is "the amount of information (self-information as defined by Shannon) contained in sᵢ, which corresponds to the number of bits needed to encode sᵢ".
  • Calculator: log₂ x = log₁₀ x / 0.30103 = ln x / 0.69315.
HELLO: p(L) = 0.4, p(H) = p(E) = p(O) = 0.2
L: log₂(1/0.4) = 1.3219 bits      H, E, O: log₂(1/0.2) = 2.3219 bits
η = 0.4 × 1.3219 + 3 × 0.2 × 2.3219 = 0.5288 + 1.3932 = 1.922 bits/symbol
whole word: at least 5 × 1.922 = 9.61 bits
Fig. 7.2Gray levelspᵢη
(a)256, all equally likely1/256 eachlog₂ 256 = 8 bits (7.4)
(b)21/3 and 2/3(1/3)·log₂ 3 + (2/3)·log₂ 1.5 = 0.528 + 0.390 = 0.918 (slide: 0.92)
  • η is largest when all N symbols are equally likely: η = log₂ N. Image (a) needs its full 8 bits per pixel and cannot be compressed losslessly.
  • η is 0 when one symbol is certain. The more skewed the histogram, the lower η.
  • η is the lower bound on the average code length, η ≤ l̄ (Eq. 7.5, cited on slide 30, textbook context).

6. Run-length coding (slides 14–15)

  • "Memoryless Source: an information source that is independently distributed. Namely, the value of the current symbol does not depend on the values of the previously appeared symbols."
  • "Instead of assuming memoryless source, Run-Length Coding (RLC) exploits memory present in the information source." If "symbols tend to form continuous groups, then such symbol and the length of the group can be coded." A group of equal symbols in a row is a run.
  • Each run becomes two entities, "a count suggesting the number of repeated symbols and the symbol itself": aaaaa becomes 5a.
BBBB EEEEEEEE CCCC D  AAAAA     22 symbols, 5 runs
4B   8E       4C   1D 5A        10 symbols
ratio = 22 / 10 = 2.2 (in symbols)

no runs:  ABCDE  →  1A1B1C1D1E   5 → 10 symbols, ratio 0.5

The single D still costs 1D. Without runs every symbol costs two, and the output doubles.

7. Repetition suppression and pattern substitution (slides 16–18)

  • Repetition suppression reserves "a specific symbol for a commonly occurring pattern". Slide 16: Abdcb followed by 44 a's becomes Abdcb and one flag symbol, 49 symbols into 6.
  • Pattern substitution groups "individual symbols into strings". Each string gets "a code, or an index, which is used every time the string appears".
  • "no pre-analysis of the message is required to create a dictionary of strings, but rather the strings are created as the message is scanned." Slide 18's pseudocode is the LZW algorithm of section 12.

8. Shannon-Fano: split the sorted list from the top (slides 19–23)

A variable-length code gives frequent symbols short codewords. Shannon-Fano builds the code tree "top-down", from the whole alphabet to single symbols.

Shannon-Fano Algorithm, a top-down approach
1. Sort the symbols according to the frequency count of their occurrences.
2. Recursively divide the symbols into two parts, each with approximately
   the same number of counts, until all parts contain only one symbol.
Left branch = 0, right branch = 1. A code is the path from the root down.

  • Ties give different trees, so Shannon-Fano is not unique. Both spend 10 bits = 2 bits/symbol, against the bound 9.61 bits.

9. Huffman: merge the two rarest from the bottom (slides 24–29)

  • Slide 24: PCM gives every sample log₂ n bits for n distinct values. That "might not be the most efficient coding scheme because some symbols occur more commonly than others."
  • Huffman works "bottom-up": join the two least probable nodes, which "can be leaf nodes or new parent nodes", until one root is left. Sorting the leaves "is not necessary" (slide 25).
ALGORITHM 7.1 Huffman Coding, a bottom-up approach
1. Put all symbols on a list sorted by frequency count.
2. Repeat until the list has only one symbol left:
   (1) pick the two lowest counts; make them children of a new parent
   (2) parent count = sum of the children; insert it, keeping the order
   (3) delete the children from the list
3. Label branches 0 and 1 from the root; a leaf's codeword is its path.

HELLO with Huffman (Fig. 7.5, slides 28–29). P1, P2, P3 are the new parent nodes.

after initialization:          L H E O
after (a) P1 = E + O = 2:      L P1 H
after (b) P2 = H + P1 = 3:     L P2
after (c) P3 = L + P2 = 5:     P3
codes L 0, H 10, E 110, O 111:  2×1 + 1×2 + 1×3 + 1×3 = 10 bits

10. Why Huffman works: prefix property, optimality, efficiency (slides 26, 30)

  • "Unique Prefix Property: No Huffman code is a prefix of any other Huffman code - precludes any ambiguity in decoding." Codewords end only at leaves.
HELLO, L = 0, H = 10, E = 110, O = 111:   stream 1011000111
read until a codeword matches:  10 | 110 | 0 | 0 | 111  →  H E L L O
with L = 0 and H = 01 (not prefix-free), "01" could be H or L + something
  • Optimality: a "minimum redundancy code", optimal "for a given, accurate, probability distribution".
  • "The two least frequent symbols will have the same length for their Huffman codes, differing only at the last bit."
  • "Symbols that occur more frequently will have shorter Huffman codes."
  • "The average code length for an information source S is strictly less than η + 1."

η ≤ l̄ < η + 1 (7.6) l̄ = Σ pᵢ lᵢ efficiency = η / l̄

slide 26:  A 0.28 00   B 0.2 10   C 0.17 010   D 0.17 011
           E 0.1 110   F 0.05 1110   G 0.02 11110   H 0.01 11111
l̄ = 0.28×2 + 0.2×2 + 0.17×3 + 0.17×3 + 0.1×3 + 0.05×4 + 0.02×5 + 0.01×5
  = 0.56 + 0.40 + 0.51 + 0.51 + 0.30 + 0.20 + 0.10 + 0.05 = 2.63 bits/symbol
η = 2.575 (slide: 2.574)    efficiency = 2.575 / 2.63 = 0.9792
a fixed 3-bit code:          efficiency = 2.575 / 3 = 0.858

The slide's code-length column prints 1 for A and 3 for B. The codes 00 and 10 have 2 bits each. With the printed lengths l̄ would be 2.55, below η, which is impossible.

11. Extended Huffman: code groups of symbols (slides 31–32)

  • "All codewords in Huffman coding have integer bit lengths. It is wasteful when pᵢ is very large and hence log₂(1/pᵢ) is close to 0." A symbol with p = 0.9 carries 0.152 bits and still costs 1 bit.
  • So group k symbols and give each group one codeword. The extended alphabet S⁽ᵏ⁾ = {s₁s₁…s₁, …, sₙsₙ…sₙ} has nᵏ symbols.

η ≤ l̄ < η + 1/k bits per original symbol (7.7)

  • "An improvement over the original Huffman coding, but not much."
  • Problem: for k ≥ 3 and n ≫ 1, nᵏ "implies a huge symbol table", impractical. 256 gray levels with k = 3 need 256³ = 16,777,216 codewords.

12. Adaptive Huffman: update the tree as symbols arrive (slides 33–36)

Plain Huffman needs the probabilities before it starts. Adaptive Huffman coding: "statistics are gathered and updated dynamically as the data stream arrives".

ENCODER                     DECODER
Initial_code();             Initial_code();
while not EOF               while not EOF
{                           {
    get(c);                     decode(c);
    encode(c);                  output(c);
    update_tree(c);             update_tree(c);
}                           }
  • Initial_code assigns "initially agreed upon codes, without any prior knowledge of the frequency counts". update_tree "(a) increments the frequency counts for the symbols (including any new ones)" and "(b) updates the configuration of the tree".
  • "The encoder and decoder must use exactly the same initial_code and update_tree routines." They see the same symbols in the same order, so their trees stay identical.
  • "Nodes are numbered in order from left to right, bottom to top." Sibling property: "all nodes (internal and leaf) are arranged in the order of increasing counts".
  • "When a swap is necessary, the farthest node with count N is swapped with the node whose count has just been increased to N+1." In Fig. 7.6 the farthest node is the highest-numbered one with count N.

13. LZW: one number for a whole string (slides 37–41)

  • "LZW uses fixed-length codewords to represent variable-length strings of symbols/characters that commonly occur together, e.g., words in English text."
  • "the LZW encoder and decoder build up the same dictionary dynamically while receiving the data." The dictionary is never sent.
  • Advantages over Huffman (slide 38): no prior knowledge of the input; "60 - 70% compression ratio for some text files"; better for repetitive data; a single pass.
ALGORITHM 7.2 LZW Compression
s = next input character;
while not EOF
{
    c = next input character;
    if s + c exists in the dictionary
        s = s + c;
    else
    {
        output the code for s;
        add string s + c to the dictionary with a new code;
        s = c;
    }
}
output the code for s;

s is the longest known string so far and c the next character. s grows while s + c is known. The first unknown s + c ends the piece: send code(s), store s + c, restart from c.

"Instead of sending 14 characters, only 9 codes need to be sent (compression ratio = 14/9 = 1.56)." This counts codes against characters. In bits it depends on the code length (section 14).

14. LZW decoding and the code the decoder has not made yet (slides 42–45)

ALGORITHM 7.3 LZW Decompression (simple version)
s = NIL;
while not EOF
{
    k = next input code;
    entry = dictionary entry for k;
    output entry;
    if (s != NIL)
        add string s + entry[0] to dictionary with a new code;
    s = entry;
}
Example 7.3, codes 1 2 4 5 2 3 4 6 1, initial table 1 = A, 2 = B, 3 = C
S     K   entry   adds
NIL   1   A
A     2   B       4 = AB
B     4   AB      5 = BA
AB    5   BA      6 = ABB
BA    2   B       7 = BAB
B     3   C       8 = BC
C     4   AB      9 = CA
AB    6   ABB    10 = ABA
ABB   1   A      11 = ABBA       output ABABBABCABABBA
  • The decoder makes the encoder's entries one code later. It learns the last character of s + c only from the next code.
  • If the encoder uses an entry right after creating it, that code reaches the decoder first. ALGORITHM 7.4 adds an exception handler: if (entry == NULL) entry = s + s[0];
  • Why s + s[0] (textbook context): the missing entry is the one about to be added, s + entry[0]. It starts with s, so entry[0] = s[0].
  • Real applications (slide 45): the code length l stays in [l₀, l_max]. The dictionary starts with 2^l₀ entries. When it is full, l grows by 1, until l = l_max.
  • Then the dictionary "needs to be flushed (as in Unix compress)", or the LRU (least recently used) entries are removed.

Mistakes that cost marks

  • Entropy with log₁₀ or ln and no conversion. Use log₂ x = log₁₀ x / 0.30103. N equally likely symbols give log₂ N: 8 symbols → 3 bits, 256 levels → 8 bits.
  • Swapping the directions. Shannon-Fano is top-down (sort, split into equal counts). Huffman is bottom-up (merge the two smallest).
  • Huffman: after a merge the parent goes back into the list. Always take the two smallest of the current list, leaves and parents alike.
  • Copying the slide's tables. Slide 26's code lengths for A and B are 2 and 2 (l̄ = 2.63). Table 7.1's bits used for L is 2 × 1 = 2.
  • LZW encoding: the encoder outputs code(s), the old string, never the entry it just added. And it outputs code(s) once more at EOF.
  • LZW decoding: a code that is not in the dictionary yet is s + s[0]. Algorithm 7.3 fails there; Algorithm 7.4 handles it.
  • RLE on data without runs: every symbol becomes count + symbol, twice as long. RLC relies on memory in the source.
  • DPCM: predict from the reconstructed f̃. Predicting from the original f makes the decoder drift.

HUFFMAN (tree, codes, l̄, η, efficiency)

2. Merge table: step | two smallest | new node | list after.
3. Draw the tree; read codes root → leaf. Check: prefix-free,
   the two rarest have the same length.

6. Check η ≤ l̄ < η + 1. Efficiency = η / l̄.
7. Fixed length ⌈log₂ n⌉ bits: compare totals or efficiencies.

SHANNON-FANO
1. Sort by count.  2. Each split: list the cuts with |left − right|,
   take the smallest; left = 0, right = 1.
3. Table: count × length, TOTAL bits.
4. Compare with fixed length N × ⌈log₂ n⌉: ratio B₀/B₁.

RLE
Runs as count, then symbol. Ratio = symbols before / symbols after.
Say why: runs (memory) shrink; no runs double the length.

LZW ENCODE   table: s | c | output | code | string
s + c known → s = s + c; else output code(s), add s + c, s = c.
EOF → output code(s). Give the code list and codes vs characters.

LZW DECODE   table: s | k | entry/output | code | string

ENTROPY, DPCM, RATIO
η = Σ pᵢ log₂(1/pᵢ): "the lower bound on l̄ of any lossless code".
Difference coding: send f₁, then fₙ − fₙ₋₁; decoder adds back.
DPCM: f̂ₙ, eₙ = fₙ − f̂ₙ, ẽₙ = Q[eₙ], f̃ₙ = f̂ₙ + ẽₙ, error fₙ − f̃ₙ.

Exam focus
  • η = Σ pᵢ log₂(1/pᵢ). Two values 1/3 and 2/3: 0.918. 256 equal levels: 8 bits. HELLO: 1.922 bits/symbol.
  • Compression ratio B₀/B₁: 4B8E4C1D5A gives 22/10 = 2.2 in symbols; LZW Example 7.2 gives 14/9 = 1.56.
  • RLC exploits memory (runs) and codes count then symbol. A memoryless source has no runs to exploit.
  • Shannon-Fano top-down, Huffman bottom-up. A15 B7 C6 D6 E5: Huffman 87 bits, Shannon-Fano 89, fixed 117.
  • l̄ = Σ pᵢlᵢ, efficiency η/l̄: slide 26 gives 2.575 / 2.63 = 0.9792.
  • η ≤ l̄ < η + 1; extended Huffman η ≤ l̄ < η + 1/k with nᵏ symbols. p = 0.9: 1 bit → 0.645 bits/symbol at k = 2.
  • Unique prefix property makes decoding unambiguous. The two rarest symbols have equal lengths and differ in the last bit.
  • Adaptive Huffman: sibling property; swap the farthest node with count N with the node going to N + 1. In Fig. 7.6 A goes 000 → 011 → 10.
  • LZW Example 7.2 outputs 1 2 4 5 2 3 4 6 1. Decoding 1 2 3 5 (1 = A, 2 = B) needs the exception and gives ABABABA.
  • DPCM: eₙ = fₙ − f̂ₙ, ẽₙ = Q[eₙ], f̃ₙ = f̂ₙ + ẽₙ; the predictor uses f̃, so errors stay within one quantization error.
