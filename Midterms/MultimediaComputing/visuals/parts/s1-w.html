Question 1 · 10 pts · Lecture 10, Morphology

Morphology

  1. (a)What is image morphology? Define the dilation operation. (5 pts)
  2. (b)Apply dilation on image A using the structuring element B. Pixels outside the image are 0. Give the result on the same 7 x 7 grid. (5 pts)

(a) What to write

  • "Morphological image processing is a collection of non-linear operations related to the shape or morphology of features in an image." It uses only the relative ordering of pixel values, so it suits binary images. The two basic operations are erosion and dilation. Opening and closing are built from them.
  • The operations use a structuring element (SE): "a small binary image, i.e. a small matrix of pixels, each with a value of zero or one". Its matrix size is its size, its pattern of 1s is its shape, and its origin is usually the centre. It plays the role of a convolution kernel.
  • Dilation: A ⊕ B = { z | (B̂)z ∩ A ≠ ∅ }, "the set of all displacements z such that B̂ and A overlap by at least one element".
  • In words, every pixel takes the maximum over the SE neighbourhood. Bright (foreground) regions grow and small gaps are joined.

(b) Worked solution

  • The cross is symmetric, so B̂ = B. B̂ is B turned 180°, see Figure 3.
  • An output pixel is 1 if the cross centred on it hits at least one 1 of A. That means the pixel itself or one of its 4-neighbours (up, down, left, right) is 1.
  • Equivalently, stamp a cross on every 1 of A. A has 8 ones, and no stamp reaches past the 7 x 7 grid.

Result: A ⊕ B has 28 ones.

  • Check (row, col from 0): (3,4) gets a 1 from (3,5), and (4,4) gets one from (4,3). The outlined pixels join the vertical bar and the bottom shape into one region ("broken segments were joined", slide 22).

What B̂ is, and where dilation uses it

  • B̂ is B turned 180° around its origin. Slide 48: B̂ = { w | w = −b, b ∈ B }, it "reflects all elements of B about the origin". Write each 1 of B as an offset (row, col) from the origin and change both signs.
  • For the Q1 cross, up (−1,0) and down (+1,0) swap, left (0,−1) and right (0,+1) swap, and the centre (0,0) stays. The same five cells come back, so B̂ = B.
  • The definition A ⊕ B = { z | (B̂)z ∩ A ≠ ∅ } checks one pixel at a time. Put the origin of B̂ on pixel z. If any 1 of B̂ lands on a 1 of A, z becomes 1.
  • Stamping B on every 1 of A (Figure 2) uses B as it is and gives the same result. The flip is what makes the two methods agree.
  • The flip only changes the answer when B is lopsided or its origin is off-centre. Switch Figure 3 to the lopsided cross to see the mistake a missing flip causes.
Exam line

Dilation: A ⊕ B = { z | (B̂)z ∩ A ≠ ∅ }, "the set of all displacements z such that B̂ and A overlap by at least one element". Each pixel takes the maximum over the structuring element, so bright regions grow.

Question 2 · 10 pts · Lecture 11, Spatial filtering

Filtering

  1. (a)Compare blurring (low-pass averaging) and median filtering. Which kind of noise does each one handle better, and what happens to edges? (4 pts)
  2. (b)The 5 x 5 gray image below contains one salt-noise pixel (255). Rows and columns are numbered from 0, so the noisy pixel is (2, 2). At pixel (2, 2) apply (i) the 3 x 3 average (blurring) mask with all coefficients 1/9 and (ii) the 3 x 3 median filter. Round to the nearest integer and say which output is better. (6 pts)

(a) What to write

  • Blurring = low-pass spatial filtering. It "removes the finer details of an image" and is done by convolution. In the common blurring mask "all convolution coefficients are equal" (3 x 3: 1/9 each), and "the bigger the mask, the greater the blurring effect".
  • Blurring is linear: the output is the mean of the window. A low-pass filter is "suited for removing Gaussian noise, but not impulse noise", and it also blurs edges.
  • Median filter: sort the pixels in the window and replace the centre with the middle value. It is non-linear. It is "an effective method for removing impulse noise" (salt and pepper) and it "preserves sharp edges and detail".
  • "Median filter is superior to lowpass filter when dealing with edges." Use averaging for Gaussian noise. Use the median for salt and pepper noise or when edges must stay sharp.

(b) Worked solution

(2, 2) is an interior pixel, so the full 3 x 3 window is available and no border rule is needed.

window   57  59  62
         58 255  63
         60  62  65

(i)  57 + 59 + 62 + 58 + 255 + 63 + 60 + 62 + 65 = 741
     741 / 9 = 82.33  → 82
(ii) sorted: 57 58 59 60 [62] 62 63 65 255
     5th of 9 values  → 62
  • The 8 clean neighbours are about 61 (mean 60.75). The median (62) removes the salt pixel completely.
  • The average (82) is still about 21 too bright, because the 255 alone contributes 255 / 9 = 28.3 to the mean. The noise is smeared, not removed.

Result: average 82, median 62. The median filter is better here.

Exam line

Low-pass (average) filter: "suited for removing Gaussian noise, but not impulse noise", and it blurs edges. Median filter: "an effective method for removing impulse noise" that "preserves sharp edges and detail".

Question 3 · 10 pts · Lecture 9, Histogram equalization

Histogram equalization

A 3-bit image (L = 8, gray levels 0 to 7) of size 4 x 4:

  1. (a)Calculate the histogram n_k for k = 0, ..., 7. (3 pts)
  2. (b)Calculate the cumulative sum and the normalized sum of the histogram. (3 pts)
  3. (c)Perform histogram equalization: give the mapping r_k -> s_k, the output image and the output histogram. (4 pts)

What to write

  • A histogram is "a simple bar graph that stands for pixel intensities": intensity on the x-axis and number of occurrences on the y-axis.
  • HE steps: 1. compute the histogram; 2. calculate the normalized sum of the histogram; 3. transform the input image to the output image (LUT).
  • Professor's convention: sk = round( (L − 1) / N² × Σj=0..k nj ) = round(cumulative sum × 7/16), rounded to the nearest integer. Here L − 1 = 7 and N² = 16.

(a) Histogram

Result: nk = 0, 3, 6, 5, 1, 0, 1, 0 (they add up to 16 pixels).

(b) Cumulative and normalized sum, (c) mapping

Result: LUT for r = 0 to 7: 0 1 4 6 7 7 7 7

(c) Mapping, output image and output histogram

  • Output histogram: n1 = 3, n4 = 6, n6 = 5, n7 = 2 (all other levels 0).
  • The peak levels 2 and 3 move apart, so contrast is stretched near the histogram maxima. Input levels 4 and 6 both map to 7.
  • The result is not flat (slide 26). With discrete levels HE can only move levels apart or merge them. It never splits one level into several.
Exam line

HE in 3 steps: compute the histogram, calculate the normalized sum of the histogram, transform the input image with it. sk = round((L − 1)/N² × cumulative sum).

Question 4 · 10 pts · Lecture 12, Pattern recognition

Pattern recognition system

  1. (a)Draw the flow chart of a pattern recognition system, from the input to the decision. (6 pts)
  2. (b)Explain each stage of the system in one line. (4 pts)

(a) Draw (slide 18, read bottom to top)

  • The solid arrows (black on the slide) are the data flowing up. The dashed arrows (gray on the slide) point down from each stage to the stage below it.
  • Side inputs: costs go into post-processing; adjustments for context go into post-processing and classification; adjustments for missing features go into classification.

(b) One line per stage (slide wording)

  • Sensing: "use of a transducer (camera or microphone)". The system depends on the transducer's bandwidth, resolution, sensitivity and distortion.
  • Segmentation and grouping: isolate each pattern from the others and from the background. "Patterns should be well separated and should not overlap".
  • Feature extraction: measure "discriminative features" that are "invariant with respect to translation, rotation and scale" (fish example: length, lightness, width).
  • Classification: "use a feature vector provided by a feature extractor to assign the object to a category".
  • Post-processing: "exploit context input dependent information other than from the target pattern itself to improve performance". It uses the costs of errors and the context, and then outputs the decision.

If the question asks for the design cycle (slide 21)

Collect data → choose features → choose model → train classifier → evaluate classifier. Evaluation feeds back to the earlier steps, and "prior knowledge (e.g., invariances)" feeds into choosing features and choosing the model.

Exam line

Input → sensing → segmentation → feature extraction → classification → post-processing → decision. Costs and adjustments for context enter post-processing; adjustments for context and for missing features enter classification.

Question 5 · 10 pts · Lecture 4, Huffman coding

Huffman coding

A source emits 5 symbols with these probabilities:

  1. (a)Build the Huffman tree and give the code of each symbol. (4 pts)
  2. (b)Compute the average code length. (2 pts)
  3. (c)Compute the entropy of the source. (2 pts)
  4. (d)Compute the coding efficiency and compare it with a fixed-length code. (2 pts)

(a) Tree and codes

  • Always merge the two smallest probabilities. This source has no ties.
  • Labelling rule: at each merge the smaller node goes left = 0 and the larger goes right = 1.
  • Any consistent 0/1 labelling gives the same code lengths, so it earns full marks.
  • No code is a prefix of another. The two least frequent symbols (D, E) have the same length and differ only in the last bit.

(b) Average length, (c) entropy, (d) efficiency

(b) l̄ = Σ p·l = 0.40(1) + 0.25(2) + 0.15(3) + 0.12(4) + 0.08(4)
      = 0.40 + 0.50 + 0.45 + 0.48 + 0.32 = 2.15 bits/symbol

(c) η = Σ p·log₂(1/p)        (log₂ x = log₁₀ x / 0.30103)
      = 0.5288 + 0.5000 + 0.4105 + 0.3671 + 0.2915 = 2.0979 bits/symbol
    check η ≤ l̄ < η + 1:  2.098 ≤ 2.15 < 3.098

(d) efficiency = η / l̄ = 2.0979 / 2.15 = 0.9758  (97.6%)
    fixed length: 5 symbols need 3 bits (2² = 4 < 5 ≤ 8 = 2³)
    efficiency = 2.0979 / 3 = 0.699  (69.9%)

Result: l̄ = 2.15 bits/symbol, η = 2.098 bits/symbol, efficiency 97.6% against 69.9% for a 3-bit fixed-length code. Huffman is 3 / 2.15 = 1.40 times shorter than the fixed-length code.

Exam line

Huffman: repeatedly merge the two least probable nodes, bottom-up. Average length l̄ = Σ pili, entropy η = Σ pi log₂(1/pi), and η ≤ l̄ < η + 1.

Question 6 · 10 pts · Lecture 2, Sampling and quantization

Audio digitization

  1. (a)Explain sampling and quantization. What is the difference between them? (4 pts)
  2. (b)A stereo song is recorded at a sampling rate of 32 kHz with 16 bits per sample. It lasts 2 minutes.
    1. iUsing the Nyquist theorem, what is the highest frequency this recording can represent? Is that enough for the full range of human hearing (up to 20 kHz)? (2 pts)
    2. iiCompute the bit rate. (2 pts)
    3. iiiCompute the uncompressed file size in MB (1 MB = 10^6 bytes). (2 pts)

(a) What to write

  • Sampling: "using measurements only at evenly spaced time intervals". The rate is the sampling frequency fs = 1/T, and the samples are xs(n) = x(nT). It digitizes the time axis.
  • Quantization: "encoding the signal value at every sampled location with a predefined precision, defined by a number of levels". b bits give 2b levels with step δ = R/2b.
  • Q rounds each sample to the nearest level, so it always introduces an error (quantization noise, at most half a step). It digitizes the amplitude axis.
  • Difference: sampling makes the time axis discrete, quantization makes the amplitude axis discrete. A/D = sampling + quantization; D/A = interpolation.

(b)(i) Nyquist

  • Nyquist: fs > 2fmax, so fmax < fs/2 = 32/2 = 16 kHz.
  • This is not enough for hearing up to 20 kHz, which needs fs > 40 kHz (CD uses 44.1 kHz). Content above 16 kHz would alias.

Result: fmax < 16 kHz, not enough for 20 kHz hearing.

(b)(ii) Bit rate, (iii) file size

(ii)  bit rate = f_s × bits × channels
            = 32,000 × 16 × 2 = 1,024,000 bit/s = 1,024 kbps  (about 1.02 Mbps)

(iii) 2 min = 120 s
      1,024,000 × 120 = 122,880,000 bits
      122,880,000 / 8 = 15,360,000 bytes = 15.36 MB
      (14.65 MiB if 1 MiB = 2^20 bytes)

Result: 1,024 kbps and 15.36 MB.

Exam line

Sampling digitizes time, quantization digitizes amplitude (2b levels, δ = R/2b). Nyquist: fs > 2fmax. Bit rate = sampling rate × bits per sample × channels.

Question 7 · 10 pts · Lecture 6, Image basics

Digital image representation

  1. (a)Define spatial resolution and intensity resolution. (4 pts)
  2. (b)A gray scale image has 1024 x 768 pixels and 256 gray levels. How many bits per pixel (k) are needed, what is the range of gray values, and how much storage does the image need in bits and in bytes? (3 pts)
  3. (c)The same image is re-quantized to 16 gray levels. Give the new k and the storage in bytes. What artifact appears in smooth regions, and why? (3 pts)

(a) What to write

  • Spatial resolution = the "smallest discernible detail" in an image. It is measured in line pairs per unit distance or dots (pixels) per unit distance, e.g. dpi. It is set by sampling (M x N). "Large image size itself does not mean high spatial resolution."
  • Intensity resolution = the "smallest discernible change in intensity level". It is given by the number of intensity levels, L = 2k, so it is set by quantization.

(b) 256 gray levels

L = 2^k = 256        → k = log₂ 256 = 8 bits/pixel
gray values          → 0 ≤ f ≤ L − 1 = 0 to 255
b = M × N × k        = 1024 × 768 × 8 = 6,291,456 bits
                     = 6,291,456 / 8  = 786,432 bytes  (768 KiB)

Result: k = 8, gray values 0 to 255, 6,291,456 bits = 786,432 bytes.

(c) 16 gray levels

k = log₂ 16 = 4
b = 1024 × 768 × 4 = 3,145,728 bits = 393,216 bytes  (half of the 8-bit image)
  • Artifact: false contouring (banding). With only 16 levels, smooth gradual shading is forced into a few flat bands of constant gray, with visible false edges (contours) between them (slide 30, skull at 16 and 8 levels).
  • Spatial resolution is unchanged. Only intensity resolution drops.

Result: k = 4, 393,216 bytes, false contouring.

Exam line

Spatial resolution = smallest discernible detail (dpi, set by sampling). Intensity resolution = smallest discernible change in intensity level (L = 2k, set by quantization). Storage b = M × N × k bits. Too few levels give false contouring.

Question 8 · 10 pts · Lecture 11, Edge detection

Edge detection

Sobel masks:

Image (5 x 5), rows and columns numbered from 0:

  1. (a)Apply Mx and My at pixel (2, 2) to get Gx and Gy. (4 pts)
  2. (b)Compute the gradient magnitude in both forms (square root form and absolute sum form) and the gradient direction. (4 pts)
  3. (c)Why does the Sobel operator also smooth the image while it differentiates? (2 pts)

(a) Apply the masks

Rule (slide 14): place the mask on the 3 x 3 window centred on (2, 2), multiply the matching positions and add (no flip).

Gx = (−10 + 40) + 2(−10 + 40) + (−40 + 90) = 30 + 60 + 50 = 140
Gy = (40 + 2·40 + 90) − (10 + 2·40 + 40)     = 210 − 130    = 80

Result: Gx = 140, Gy = 80.

(b) Magnitude and direction

square root form   |G| = √(140² + 80²) = √(19600 + 6400) = √26000 = 161.25
absolute sum form  |G| ≈ |Gx| + |Gy| = 140 + 80 = 220
direction          θ = tan⁻¹(Gy / Gx) = tan⁻¹(80 / 140) = tan⁻¹(0.5714) = 29.74°
  • θ = 29.74° is the gradient direction, pointing toward the brighter pixels (down and right). The edge runs perpendicular to it.
  • Sign check: with slide 37's Hr = [1 0 −1; 2 0 −2; 1 0 −1], Gx = −140 and θ = −29.74°. With true (flipped) convolution both signs flip (Gx = −140, Gy = −80), so tan⁻¹(Gy/Gx) is again 29.74°. The magnitude does not change.

Result: 161.25 (square root form), 220 (absolute sum form), θ = 29.74°.

(c) Why Sobel also smooths

  • (textbook context) Each Sobel mask is a smoothing filter times a difference filter: Mx = [1 2 1]ᵀ × [−1 0 1]. It takes a central difference across the edge, and at the same time a weighted average [1 2 1] of three rows along the edge, with the centre row weighted 2.
  • This built-in averaging (low-pass) reduces noise. The 2 x 2 Roberts operator has a "smaller effective area" and is "more susceptible to noise" (slide 38).
  • Sobel is still listed as "highly sensitive to noise" (slide 44) compared with detectors that smooth first, such as LoG.
Exam line

Gx and Gy from the two Sobel masks; |G| = √(Gx² + Gy²) or |Gx| + |Gy|; θ = tan⁻¹(Gy/Gx). Sobel weights the centre row by 2, which smooths, so it is less noisy than Roberts.
