Lecture 12 · Week 7 · 10 sample questions

Pattern Recognition from Zero

How a machine measures an object, turns it into a few numbers, and decides which group it belongs to. The lecture follows one example, sorting salmon from sea bass on a conveyor, from the camera to the decision. Then it shows the classifiers that make the decision: nearest class mean, nearest neighbour and Bayes.

Words you need

Pattern

"An arrangement of descriptors" (slide 3). One object as the machine sees it, for example one fish.

Feature (descriptor)

One measured number about a pattern: a fish's length, lightness or width, a character's number of holes.

Pattern class

"A family of patterns that share some common properties" (slide 3): salmon, sea bass, the letter A.

Feature vector x

The features of one pattern in a list, x = [x₁, x₂, …, xd]. Fish: x = [lightness, width].

Feature space

A plot with one axis per feature. Every pattern is one point, and similar patterns land close together.

Decision boundary

The border between class regions of feature space: a threshold x* for one feature, a line or curve for two.

Classifier

"Assigns object to a class based on features" (slide 36), or to the reject class.

Reject class

"A generic class for objects not in any of the designated known classes" (slide 36).

Training set

Example patterns whose class is known. The classifier is built from them. New patterns are novel input.

1. Patterns, features and pattern classes (slides 2–3)

Pattern recognition makes a machine do what you do when you recognise a face or a letter: measure an object, then name its group. The slide 2 contents: background, patterns and pattern classes, classification by prototype matching, template matching, the statistical classifier.

  • "A pattern is an arrangement of descriptors."
  • "The name feature is used often in the pattern recognition literature to denote a descriptor."
  • "A pattern class is a family of patterns that share some common properties."
  • Fish example: one fish is a pattern, its lightness is a feature, salmon is a pattern class.

2. The fish example: task and preprocessing (slides 4–7)

  • Task (slide 4): "Sorting incoming Fish on a conveyor according to species using optical sensing". Species: sea bass or salmon.
  • Problem analysis (slide 5): "Set up a camera and take some sample images to extract features": length, lightness, width, number and shape of fins, position of the mouth. "This is the set of all suggested features to explore for use in our classifier!"
  • Preprocessing (slide 6): "Use a segmentation operation to isolate fishes from one another and from the background". Then "information from a single fish is sent to a feature extractor whose purpose is to reduce the data by measuring certain features". Then "the features are passed to a classifier".
  • Slide 7: camera image → preprocessing → feature extraction → classification → "salmon" or "sea bass". A whole image goes in; two or three numbers per fish come out.

3. One feature, a threshold, and the cost of mistakes (slides 8–11)

Measure one feature on many fish whose species you know, and draw one histogram per species (slides 8–10). Then pick a threshold and call everything on one side salmon.

length < l* → salmon lightness < x* → salmon otherwise → sea bass

  • Two errors exist: a sea bass labelled salmon, and a salmon labelled sea bass. Where the histograms overlap, some fish are always on the wrong side.
  • Length overlaps heavily (l* ≈ 11 on slide 9): "The length is a poor feature alone! Select the lightness as a possible feature."
  • Lightness overlaps much less (x* ≈ 5.5 on slide 10). Salmon are darker, sea bass lighter.

Fewest errors is not always the goal. Slide 11: "Move our decision boundary toward smaller values of lightness in order to minimize the cost (reduce the number of sea bass that are classified salmon!)". Choosing the boundary from costs is the "task of decision theory". (textbook context: buyers accept a piece of salmon in a sea bass can but complain about sea bass in a salmon can.)

total cost = c × (sea bass labelled salmon) + 1 × (salmon labelled sea bass)

4. Two features, the best boundary and generalization (slides 12–16)

  • Slide 12: "Adopt the lightness and add the width of the fish". Each fish becomes xT = [x₁, x₂] = [lightness, width], a point in a 2D feature space, and a straight line separates the clouds better than one threshold (slide 13).
  • Slide 14: "We might add other features that are not correlated with the ones we already have. A precaution should be taken not to reduce the performance by adding such noisy features". It then shows a very wiggly boundary that puts every training fish on its correct side: "the best decision boundary should be the one which provides an optimal performance".
  • Slide 15: "our satisfaction is premature because the central aim of designing a classifier is to correctly classify novel input". This is the issue of generalization.
  • Slide 16 settles on a smooth curve that accepts a few training errors and does better on new fish. (textbook context: a boundary that fits the noise of the training set is overfitted.)

5. The pattern recognition system (slides 17–19)

Slide 18 turns the fish chain into the general system, drawn from the input at the bottom to the decision at the top, with classification highlighted. Every sample exam asks you to draw it.

Sensing"Use of a transducer (camera or microphone)". "PR system depends of the bandwidth, the resolution sensitivity distortion of the transducer"camera over the belt
Segmentation and grouping"Patterns should be well separated and should not overlap"cut each fish out
Feature extraction"Discriminative features". "Invariant features with respect to translation, rotation and scale."lightness, width
Classification"Use a feature vector provided by a feature extractor to assign the object to a category"salmon or sea bass

  • Invariant means the number stays the same when the object moves (translation), turns (rotation) or changes size (scale).
  • Side inputs: costs → post-processing; adjustments for context → post-processing and classification; adjustments for missing features → classification.

6. The design cycle (slides 20–27)

Section 5 is the finished machine. The design cycle is how you build it (slide 21): collect data → choose features → choose model → train classifier → evaluate classifier. Evaluation feeds back to the earlier boxes, and "prior knowledge (e.g., invariances)" feeds choose features and choose model.

  • Slide 31: "A class is a set of objects having some important properties in common". "A classifier is a program that inputs the feature vector and assigns it to one of a set of designated classes or to the reject class."

8. Feature vectors, characters and template matching (slides 32–36, 48)

  • Slide 32: X = [x₁, x₂, …, xₙ], "each xⱼ a real number". xⱼ "may be an object measurement" or "may be count of object parts". Example: [#holes, #strokes, moments, …].
  • Slide 33: the E-13B bank font and its waveforms. Slide 34: features per character. A and 0 both have 1 hole, B and 8 both have 2, so one feature cannot separate them; the vector [#holes, #strokes, width, …] can (A has 3 strokes, 0 has none).
  • Slide 36: classes are "m known categories of objects"; reject class "a generic class for objects not in any of the designated known classes"; classifier "assigns object to a class based on features".
  • Template matching (slide 35): a template w of m × n pixels is centred at every location (x, y) of the image f, as a filter mask in Lecture 11. The image is padded with (m − 1)/2 rows and (n − 1)/2 columns; a 5 × 3 template needs 2 rows and 1 column.
  • Slide 48: the template of a hurricane's eye, the correlation coefficient shown as an image, and the best match at its brightest point. (textbook context) γ = Σ(w − w̄)(f − f̄) / √(Σ(w − w̄)² Σ(f − f̄)²), between −1 and 1; the maximum is the best match.

9. Discriminant functions and the nearest class mean (slides 37–38)

Slide 37: "Functions f(x, K) perform some computation on feature vector x". "Knowledge K from training or programming is used". "Final stage determines class". One function per class; with distances the smallest wins (textbook context).

Slide 38: "Compute the Euclidean distance between feature vector X and the mean of each class. Choose closest class, if close enough (reject otherwise)."

xc = average of the samples of class c ‖x − xc‖ = √( Σᵢ (x[i] − xc[i])² )

Class A = (1,1) (2,1) (1,2) (4,4)     Class B = (6,6) (8,6) (7,8) (7,4)
mean A = ((1+2+1+4)/4, (1+1+2+4)/4) = (2, 2)
mean B = ((6+8+7+7)/4, (6+6+8+4)/4) = (7, 6)
x = (5, 4):  d_A = √(9 + 4) = 3.606   d_B = √(4 + 4) = 2.828 ← smallest, ≤ 3 → B
x = (4, 10): d_A = √(4 + 64) = 8.246  d_B = √(9 + 16) = 5.000 ← smallest, > 3 → reject

10. Two modes and scaling by σ (slides 39–40)

  • Slide 39: "Nearest mean might yield poor results with complex structure". "Class 2 has two modes; where is its mean." Its modes sit near (0.18, 0.83) and (0.57, 0.31), so one mean lands near (0.38, 0.57), in empty space. "But if modes are detected, two subclass mean vectors can be used."
  • Slide 40: scale each difference "by the spread, or standard deviation, σᵢ of class c along each dimension i".

‖x − xc‖ = √( Σᵢ ((x[i] − xc[i]) / σᵢ)² )

X = (0.2, 0.62)   Class 2: mean (0.2, 0.80), σ = (0.10, 0.10)   Class 3: mean (0.2, 0.35), σ = (0.05, 0.20)
Euclidean: d₂ = 0.18          d₃ = 0.27          → Class 2
scaled:    d₂ = 0.18/0.10 = 1.80   d₃ = 0.27/0.20 = 1.35   → Class 3 (the slide's conclusion)

11. Nearest neighbour and k nearest neighbours (slide 41)

  • "Keep all the training samples in some efficient look-up structure."
  • "Find the nearest neighbor of the feature vector to be classified and assign the class of the neighbor."
  • "Can be extended to K nearest neighbors." (textbook context) The k closest samples vote; use an odd k with two classes.
  • Nearest mean stores one vector per class. Nearest neighbour stores every sample: more memory, but it follows any class shape.

12. Bayesian decision making (slide 42)

"Classify into class ωᵢ that is most likely based on observations X". Needed: (1) the class conditional distribution p(x | ωᵢ), (2) the a priori probability P(ωᵢ), (3) the unconditional distribution p(x), (4) "use Bayes rule if all of the classes ωᵢ are disjoint".

P(ωᵢ | x) = p(x | ωᵢ) P(ωᵢ) / p(x) p(x) = Σⱼ p(x | ωⱼ) P(ωⱼ)

made-up: P(salmon) = 0.7, P(sea bass) = 0.3; at the measured x: p(x | salmon) = 0.2, p(x | sea bass) = 0.6
p(x) = 0.2 × 0.7 + 0.6 × 0.3 = 0.14 + 0.18 = 0.32
P(salmon | x) = 0.14 / 0.32 = 0.4375    P(sea bass | x) = 0.18 / 0.32 = 0.5625 → sea bass
with P(salmon) = 0.9: p(x) = 0.24, posteriors 0.75 and 0.25 → salmon

(textbook context) Pick the class with the largest posterior. p(x) is the same for every class, so comparing p(x | ωᵢ) P(ωᵢ) is enough.

13. The lecture's examples (slides 43–47)

  • Iris (slides 43, 47): x₁ = petal length, x₂ = petal width. The minimum distance boundary for versicolor vs setosa is 2.8x₁ + 1.0x₂ − 8.9 = 0, the perpendicular bisector between the two means. x = (3, 1): 8.4 + 1.0 − 8.9 = +0.5 > 0 → versicolor.
  • Slide 44, Table 12.1, Bayes classification of multispectral image data: % correct = diagonal / row total, e.g. 885 / 933 = 94.9 %. Overall: training 1831 / 1900 = 96.4 %, independent 1824 / 1897 = 96.2 %. The independent (unseen) set is the honest measure.
  • Slides 45–46: a noisy object and its signature r(θ); a satellite image of Washington, D.C.

Mistakes that cost marks

  • Reordering the stages. Bottom to top: input, sensing, segmentation, feature extraction, classification, post-processing, decision.
  • Sending costs into classification. Costs → post-processing only; context → both; missing features → classification only.
  • Mixing up the system (one input to a decision) with the design cycle (building the classifier, with feedback).
  • Swapping supervised (teacher labels) and unsupervised (system forms clusters).
  • Calling the reject class the largest class or the pixels removed in segmentation.
  • Stopping at "closest" when a reject threshold is given. Check d ≤ T, or d² ≤ T² if you skipped the root.
  • Confusing nearest class mean (one average per class) with nearest neighbour (all samples kept).
  • Moving x* the wrong way: to cut sea bass labelled salmon, move it toward smaller lightness.

Cheat sheet

How to write it on the exam

Draw the PR system + one line per stage
  boxes bottom to top: sensing, segmentation, feature extraction, classification,
  post-processing; input below, decision on top; solid arrows up, dotted arrows down
  costs → post-processing; context → post-processing and classification;
  missing features → classification; then one slide line per stage

Draw the design cycle
  start → collect data → choose features → choose model → train → evaluate → end
  evaluation feeds back; prior knowledge → features and model; + computational complexity

Nearest class mean with reject threshold T
  rule (slide 38) → means → d = √(Δ₁² + Δ₂²) per class → smallest → d ≤ T ? class : reject

1-NN and k-NN
  rule (slide 41) → table: sample, class, Δ, d², d → sort → rank 1 → vote of ranks 1..k
  say whether they agree and why (one close sample vs majority)

Fish reasoning
  length overlaps → poor alone; lightness better; add width → line in 2D;
  boundary = border between class regions; cost → move x* toward smaller lightness;
  generalization = correct on novel input
Exam focus
  • Input → sensing → segmentation → feature extraction → classification → post-processing → decision, with the three side inputs.
  • Feature extraction: discriminative, invariant to translation, rotation and scale. Post-processing: exploit context.
  • Supervised = teacher labels; unsupervised = clusters. Statistical = vectors; structural = grammar or graph.
  • Nearest mean: means (2, 2), (7, 6); x = (5, 4) → 3.606 vs 2.828 → B; x = (4, 10) → 5.0 > 3 → reject.
  • NN: x = (5, 4) → 1-NN A (1.000); 3-NN A, B, B → B.
  • Bayes: 0.14 / 0.32 = 0.4375 vs 0.5625 → sea bass.
