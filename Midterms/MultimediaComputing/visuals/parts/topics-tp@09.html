Histograms and Point Operations from Zero

A point operation gives every pixel a new value that depends only on its own old value, so one small table, the look-up table, can process a whole image. This lecture builds on that idea: the histogram, histogram equalization and specification, and pixel-by-pixel arithmetic and logic. It uses the gray levels of Lecture 6 and the image operations of Lecture 7.

Words you need

Gray level r, s and L

The number stored in a pixel. r is the input level, s the output level. With L levels they run 0 to L − 1: 3-bit means L = 8 (0 to 7), 8-bit means L = 256.

Point process, s = T(r)

The new value of a pixel depends only on its own old value. T is the rule, drawn as a curve from r (x-axis) to s (y-axis).

Look-up table (LUT)

T written out as a table, one entry per input level. The pixel value is the index; the entry at that index is the new value.

Histogram nk

The number of pixels at each gray level k, drawn as a bar graph. The counts add up to the number of pixels.

Normalized histogram p(rk)

nk divided by the number of pixels (N² for an N × N image): the share of pixels at level k. The shares add up to 1.

Cumulative and normalized sum

The cumulative sum n0 + … + nk counts the pixels at level k or darker. The slides' normalized sum is that count × (L − 1)/N².

Histogram equalization (HE)

A LUT built from the normalized sum. It spreads the levels over the whole range, aiming at a uniform (flat) histogram.

Histogram specification

A LUT that moves the histogram toward a desired shape given by the user: z = G⁻¹[T(r)].

Clamping

Forcing a result back into 0 to 255: negative values become 0, values above 255 become 255 (slide 52).

Bitwise operation

NOT, AND, OR or XOR applied to each of the 8 bits of a pixel separately, bit 7 (worth 128) down to bit 0 (worth 1).

2. Point processes and the spatial-domain model (slides 7–8)

  • Point processes are "the simplest of the basic image processing operations", "based solely in the pixel's value", and "easily implemented as look-up tables" (slide 7).
  • The general model (slide 8) is g(x, y) = T[f(x, y)]: f is the input image, g the processed image, T an operator "defined over some neighborhood of (x,y)". The slide draws a 3 × 3 neighbourhood.
  • Shrink the neighbourhood to the pixel itself (1 × 1) and T sees one number only. That is point processing, the subject of this lecture. Larger neighbourhoods are filters (Lecture 11).

g(x, y) = T[f(x, y)] → 1 × 1 neighbourhood → s = T(r)

3. Look-up tables (slides 9–12)

An image has hundreds of thousands of pixels but only 256 (or 8) possible values. So T is computed once per value and stored in a table, and each pixel just looks its answer up.

  • "An LUT is simply a table of cross-references linking index numbers to output values." Used for display it "is often called simply a colormap" (slide 9).
  • Each pixel value "is instead treated as an index number into the colormap". Advantage: "the index number can be made to use fewer bits than the output value in order to save storage space".
  • Slide 10: addresses 0 to 255 hold brightnesses 0, 3, 7, 11, 16, …. Pixel value 4 reads address 4 and 16 goes to the monitor. The default LUT is the identity, a straight line.
  • Slide 11: "use the current pixel value as the array index"; the "new value is the array element pointed by this index". The index starts at 0.
slide 11 LUT   index   0  1  2  3  4  5  6  7
               output  0  0  1  1  2  3  4  5

4. The model of point processing, s = T(r) (slides 13, 2)

  • Point processing is "the simplest form of T": a "1 x 1 neighbor", so "g depends only on the value of f at (x,y)". It is a "gray-level transformation (or mapping)" s = T(r).
  • Read T as a curve. On the diagonal nothing changes; above it a level gets brighter, below it darker.
  • The slope is contrast. Steeper than the diagonal, neighbouring levels move apart. Flatter, they move together. A flat piece merges levels.
  • Slide 13(a), contrast stretching: an S-curve darkens levels below m and brightens those above. Slide 13(b), binarization: a step at m.

5. The histogram (slide 14)

  • "A simple bar graph that stands for pixel intensities." Intensities go on the x-axis and "the number of occurrences for each intensity" on the y-axis.
  • It gives "information about contrast and overall intensity distribution of an image". It does not say where the pixels are (textbook context).
  • To build it, scan the pixels once and add 1 to the bin of each pixel's level. Check that the bins add up to the pixel count.

7. Histogram equalization: goal, steps and theory (slides 20–25)

A low-contrast image uses a few crowded levels. Histogram equalization finds the LUT that spreads them out, using only the image's own histogram.

  • Goal (slide 20): "to obtain a uniform histogram for the output image", mapping r to s so that "the distribution of gray level s is uniform".
  • Steps: 1. Compute histogram. 2. Calculate normalized sum of histogram. 3. Transform input image to output image.
  • Condition (a) (slide 21): T(r) is single-valued and monotonically increasing on [0, 1], so dark stays darker than bright and r = T⁻¹(s) exists.
  • Condition (b): 0 ≤ T(r) ≤ 1 for r in [0, 1]. The output stays in the input's range.
  • Treat levels as random quantities with densities pr(r) and ps(s) (slide 23). Choose T = the CDF, the area under pr from 0 to r (slide 24). Then ds/dr = pr(r), so ps(s) = pr(r) × 1/pr(r) = 1, a "uniform density".

s = T(r) = ∫₀ʳ pr(w) dw ps(s) = [pr(r) dr/ds]r = T⁻¹(s) = 1

slide 25: p_r(r) = 2 − 2r   (many dark pixels, few bright)

8. What HE does, and the discrete formula (slides 26–28)

  • HE "stretches contrast ... for gray levels near histogram maxima" and "compresses contrast in areas with gray levels near histogram minima" (slide 26). It "usually improves the detectability of many image features".
  • "The resulting histogram is not flat": all pixels of one level get the same new level, so bars move and merge but never split.
  • Slides 27–28 [D.H. Ballard]: g(s) ds = h(r) dr, with h the input histogram and g the new one. A uniform g gives the normalized cumulative histogram below.
  • The worked example uses the factor 7/16 for a 3-bit, 16-pixel image, so M is used as L − 1 = 7. The brightest used level then lands exactly on 7.
  • N² is the pixel count: 16 for 4 × 4, 25 for 5 × 5, 64 for 8 × 8. Round to the nearest integer.

T(r) = (M / N²) ∫₀ʳ h(w) dw → sk = round( (L − 1)/N² × Σj=0..k nj )

10. HE on real and color images (slides 32–39)

  • Slide 32: a narrow mid-range histogram spreads over 0 to 255 and the image gains contrast. Slide 33: Lena with 256 levels, comb gaps in the output.
  • Slide 34: "Original Image / 4" keeps 64 levels; equalized it looks harsh, with 64 sparse bars. HE cannot create new levels.
  • Color (slides 35–39): equalizing the saturation gives more vivid colors (37). Equalizing only the intensity keeps the colors. Equalizing R, G and B each on its own shifts the colors (a bluish cast on slide 39), because it changes their balance (textbook context).

11. Histogram specification (slides 40–45)

  • Purpose (slide 40): "Specify particular histogram shapes capable of highlighting certain gray-level ranges", to "lighten or darken an image" or get "more contrast". It "requires both a desired histogram and the image as input".
  • "The principle difficulty ... lies in being able to construct a meaningful histogram": 1. specify a probability density function, or 2. a histogram shape "by means of graphic device".
  • Steps (slide 41): histograms of input and target; the CDF of both; the mapping that relates the two CDFs; apply it.
  • Slide 43's block diagram: original → histogram equalization → inverse histogram equalization (fed by the desired histogram) → result.

12. Arithmetic operations (slides 46–53)

  • "Addition & subtraction: adjusting the brightness of the image", I(x, y) + a = I′(x, y). "Adding and subtracting cannot adjust the contrast": every difference between two pixels stays the same (slide 48).
  • "Division, Multiplication: adjust the contrast". It is "increased by multiplication and decreased by division" (slide 50): every difference is scaled. Figure 3 shows both on a histogram.
  • Results "can generate negative values or values greater than the maximum". Clamping "sets to 0 for negative values and to 255 for overflow values" (slide 52).
  • "Subtraction: motion detection". In two video frames whatever did not move cancels to 0 and the moving object is left (slide 49). Uses (slide 53): blood-flow paths in medical imaging, inspection of printed circuits, security monitoring.
  • Adding two images blends them (slide 49).

13. Logic operations (slides 54–59)

Write each pixel in 8-bit binary, apply the rule to each column of bits, and read the result back as a number.

  • XOR (slide 56): "sets bits that are the same in each operand to 0 and bits that are different to 1". So p XOR v = 0 exactly when p = v: it "sets the pixels that are specified to black, others to nonblack".
  • Uses: "to find all pixels of a certain value", "to draw a cursor for the mouse", "for some special effects". Drawing the cursor twice restores the background, since (p XOR v) XOR v = p (textbook context).
  • Slide 57: XOR 128 flips only the top bit (100 → 228, 200 → 72), a harsh image.
  • AND and OR work with a mask (slides 58–59). A mask of 255 keeps a pixel under AND; a mask of 0 makes it black. Under OR, 0 keeps the pixel and 255 makes it white.
  • Slide 58's result shows the face with a white disk. With its mask (white disk, black frame) that is the OR result; AND keeps the face inside the disk and blacks out the rest.

Mistakes that cost marks

  • Counting a LUT from 1. The index starts at 0: in 1 2 3 3 4 6 7 7, LUT[5] = 6, not 4.
  • Scaling with L. For 3 bits the factor is (L − 1)/N² = 7/N², so the brightest used level lands on 7.
  • Rounding down. Round to the nearest: 4.8125 → 5, 3.9375 → 4.
  • Wrong pixel count. N² is the number of pixels: 25 for 5 × 5, 64 for 8 × 8. Check that the nk add up to it.
  • Calling the equalized histogram flat. Discrete levels move and merge, never split (slide 26).
  • Swapping T and G. Specification is z = G⁻¹[T(r)]; keep G(z) unrounded and take the closest, smallest z on a tie.
  • Saying addition changes contrast. + and − change brightness, × and ÷ change contrast. Clamp: 270 → 255, −10 → 0.
  • Reversing XOR. Equal bits give 0, different bits 1. NOT p = 255 − p.

Cheat sheet

How to write it on the exam

Histogram equalization (s1-w3, s2-w3, s4-w3, s5-w3)
1. Histogram: bar graph of n_k, levels on x, counts on y. HE goal: a uniform output histogram.
2. Steps: compute histogram, calculate normalized sum, transform with a LUT.
3. Rule: s_k = round((L − 1)/N² × Σ_{j≤k} n_j)          L − 1 = 7, N² = pixel count
4. Table r_k | n_k | cumulative | × 7/N² | s_k            check Σ n_k = N²
5. LUT, output image, output histogram (add the n_k that land on the same s).
6. Not flat: discrete levels move and merge, never split; contrast stretched near the peaks.

Histogram specification (s3-w3)
1. s = T(r) (equalize the image), v = G(z) (equalize the desired histogram), z = G⁻¹[T(r)].
2. T(r) rounded; G(z) unrounded; each s → z with the closest G(z), smallest z on a tie.
3. LUT r → z, output image and histogram: close to the target, not exact.

LUT (s2-mc7, s5-w3 c)
new value = LUT[value], index from 0; describe the shape (S-curve = contrast stretching).

Arithmetic and logic (s4-mc7, s5-w7)
+ / − brightness, × / ÷ contrast: show two pixels and their difference; clamp to 0..255.
bitwise: both values in 8-bit binary, column by column, back to decimal; NOT p = 255 − p.
Exam focus
  • HE: histogram, normalized sum, LUT; sk = round((L − 1)/N² × cumulative sum). Slide 29: n = 1 2 2 6 5 0 0 0 → LUT 0 1 2 5 7 7 7 7.
  • Goal: a uniform histogram; "the resulting histogram is not flat". Stretches contrast near maxima, compresses near minima.
  • Theory: T = CDF gives ps(s) = 1. Conditions (a) single-valued, monotonically increasing; (b) 0 ≤ T(r) ≤ 1.
  • Specification: z = G⁻¹[T(r)], needs the image and a desired histogram. Slide 44: G = 0 0 0 0 0 2.625 4.8125 7 → 0 0 5 5 6 6 7 7.
  • LUT: pixel value = index. 0 0 1 1 2 3 4 5 turns 7 6 4 3 0 into 5 4 2 1 0.
  • + / − brightness (histogram shifts), × / ÷ contrast (stretches). Clamp to 0..255. Subtraction: motion detection.
  • NOT 147 = 108, 147 AND 102 = 2, 147 OR 102 = 247; p XOR v = 0 only when p = v.
  • uint8 0–255, int8 −128–127, uint16 0–65535, int16 −32768–32767; RGB 24 bits per pixel.
